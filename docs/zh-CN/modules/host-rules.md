# 宿主规则与模块边界

适用契约：1.6。本文约束所有模组和宿主适配器，不按某一个示例或第三方产品追加特殊行为。注册表、事件总线、服务的基础规则见[平台规范](../../../mods/README.md)，签名见 [API 参考](api.md)。

## 设置导航

一个 `IModuleSettings` 贡献最多产生一个侧栏入口。多个 `ModuleWidget.SettingsId` 可以引用同一个本模组设置贡献；不能据此复制设置页。需要独立位置、图标和顺序时，实现可选接口 `IModuleSettingsNavigation`。

| `Placement` | 归属 | 显示条件 |
| --- | --- | --- |
| `Automatic` | 有关联组件放小程序，无关联组件放模组 | `Visible`；小程序位置还要求小程序总开关开启，至少一个关联组件开启 |
| `Modules` | 模组下的独立设置 | `Visible`，不受组件开关或小程序总开关隐式控制 |
| `MiniApps` | 小程序下的设置 | `Visible`、小程序总开关；有组件关联时至少一个开启，无关联时允许独立展示 |

停用模组会撤销它的全部贡献。`Visible` 是作者自己的业务决定，宿主不会替作者强制改为真。没有实现导航接口时按关联组件的最小顺序排列；实现后采用其 `Order`（默认 500）。模组之间先按模组 ID 排列，同组按顺序及贡献 ID 稳定排序。

`IconPath` 是不超过 4096 字符的 WPF Geometry 路径。未指定时尝试关联组件图标，仍没有则用宿主默认图标。非法位置回退 Automatic，非法图标回退默认图标，产生非致命诊断。图标只负责含义，不要把启用状态编码在图标里。

## 视图挂载、显示与释放

这三个概念不同：

| 状态 | 含义 |
| --- | --- |
| 已挂载 | 独立视图已创建，宿主拥有其资源和布局 |
| `context.IsVisible` | 宿主此刻把该视图作为可交互内容呈现 |
| 已释放 | 上下文取消，资源释放；不能再次挂载旧视图或继续导航 |

`IsVisible` 初始为 false。异步工厂等待期间始终为 false；完成布局和初始刷新后，宿主依据实际呈现决定是否切为 true。页被收起、切换到控制条、窗口隐藏／最小化、全屏抑制或临时通知遮挡时会关闭相应视图的呈现。紧凑活动被遮挡后恢复时会再次变为 true。线条模式使用宿主进度指示，不把紧凑视图标为可见。

这不是桌面像素遮挡检测：别的应用覆盖窗口、鼠标移走、设置窗口遮住岛，不等于宿主主动隐藏。离开页面可能释放视图，单纯收起也可能保留同一视图。不能依赖 WPF `Loaded`／`Unloaded` 判断业务开始结束。

`OnVisibilityChanged` 在视图 UI 线程订阅，只报告后续变化，不立即重放当前值；订阅后读取 `IsVisible` 完成初始同步。重复状态不通知。正常 UI 释放会先报告最后一次 false；来自其他线程的取消立即使 `IsVisible` 为 false，最终清理由 UI 线程完成。不要等待“最后一次回调”才保存重要数据。

`EveryVisible` 同样要求视图 UI 线程，间隔 16 ms–1 天；只在可见期间运行。隐藏时停止计时器，重新可见后重新开始一个间隔，不补发隐藏期间的 tick，也不立即执行回调。需要立刻刷新时使用可见性回调。计时器句柄提前释放后不会因再次显示重启。旧 `Every` 保持挂载生命周期语义，隐藏不停止。

## 字段定义与诊断

宿主最多读取和展示一个贡献的前 128 个设置字段。键须非空、不含控制字符且不超过 80 字符，区分大小写且不能重复；后续重复项忽略。字段有有效类型及不超过 160 字符的标签。分组、说明、占位符上限分别为 80、1000、256 字符；缺失英语文案回退中文。

| 类型 | `Read` 值与约束 |
| --- | --- |
| Toggle | `bool` |
| Number | .NET 整数、float、double 或 decimal；排除字符串、布尔、字符与日期；值有限且在有限的 Minimum/Maximum 范围内，Minimum 小于 Maximum，Step 有限且大于零 |
| Choice | `int`；必须在 1–128 个唯一整数选项中 |
| Text | `string`；长度不超过 MaximumLength，后者为 1–8192，默认 256 |
| Color | `string`，仅 `#RRGGBB`；显示时转大写，不隐式回写 |

字段**定义**无效（缺键、类型未知、范围颠倒、选项重复）时跳过该字段；**值**无效（越界、类型不符、选项已不存在）时夹取到最近的合法值照常显示，并记一条 `coerced-setting-value` 诊断——丢掉字段等于拿走用户唯一能修正它的控件。其他字段和模组继续工作。读取字段值使用 **250 毫秒**累计预算：超出后停止调用剩余字段并记一条 `settings-read-slow`；预算在同步调用返回后检查，无法中断单个阻塞 getter 或 Fields／选项枚举器，作者仍须避免阻塞 UI。在模组管理详情提供 `ModuleInfo.Diagnostics`，按本次激活、来源和代码去重，全局最多保留 200 项，重载不沿用上一代。诊断不增加运行错误计数。作者的 getter、读写或枚举器实际抛出异常仍进入故障记录，不能靠诊断机制掩盖运行错误。

`Write`、`Reset`、默认值、数据规范化和持久化仍由作者实现。宿主只提交当前有效贡献的操作，不统一代写 JSON，也不提供跨字段事务。完整设置修订、秘密存储、条件字段和批量提交尚未提供。

## 签名

包内可选文件 `BRIMDECK.SIG` 记录发布者签名。宿主在发现时校验，结果有四种：

| 状态 | 含义 | 展示 |
| --- | --- | --- |
| `Verified` | 签名有效，且签名后文件未改动 | 绿色「官方认证」 |
| `Beta` | 签名有效，但密钥属于先行测试渠道 | 紫色「先行测试」 |
| `Unsigned` | 没有签名文件（第三方模组的常态） | 折叠行不显示徽章 |
| `Invalid` | 校验失败，带原因 | 黄色「签名不匹配」，tooltip 写原因 |

原因有 `digest-mismatch`、`mod-mismatch`、`unknown-key`、`revoked-key`、`revoked-mod`、`bad-signature`、
`malformed`、`unverifiable`、`channel-mismatch`。渠道以宿主信任的密钥配置为准；包内 `channel` 必须与密钥一致，未知渠道或将 beta 改写成 release 都会拒绝。密钥与撤回列表随宿主发布，**不联网查询**；轮换或吊销都要发新版。

签名摘要 v1 与绑定启用确认的内容摘要是**两套算法**：前者按每个文件一行 `<sha256>  <相对路径>`（按码元排序、
NFC 规范化）再做一次 sha256，并排除 `BRIMDECK.SIG` 与 `.DS_Store` / `Thumbs.db` / `desktop.ini`；被签名的消息
是固定六行（`brimdeck-signature/1`、modId、modVersion、digest、keyId、signedAt），所以改版本号也会失效。
算法当前为 `ES256`（ECDSA P-256 + SHA-256，密钥为 base64 SPKI）。

签名摘要、运行时发现、内部引用检查、复制和静态检查共用有界目录遍历：最多 64 层、6000 项、2000 个文件、64 MiB，拒绝文件、目录和上层路径中的链接。发现期间前后摘要不一致时拒绝该次结果，避免将旧清单与新文件混用。内部引用逐个检查所有子目录 DLL；本机库或损坏的 PE 不会使剩余 DLL 被跳过，读取失败则拒绝该包。

**签名不是沙箱**：它证明的是"谁发布过这些字节、之后没被改动"，签名模组启用后仍与任何模组一样同进程运行。

## 内部接口与宿主版本

契约程序集是 `BrimDeck.Modules.Abstractions` 和 `BrimDeck.UI`；`BrimDeck`、`BrimDeck.Core`、`BrimDeck.Modules`
是宿主内部实现，**没有兼容性承诺**。运行时扫描包内每个 DLL 的直接程序集引用：发现引用内部程序集时，清单必须声明
`host.minimumVersion`（可加 `host.maximumVersionExclusive`），否则该包被拒绝并说明原因；声明了范围的包照常加载，
并在管理页标出「使用内部接口，要求 BrimDeck …」。宿主版本不在声明范围内时，模组**列出但不激活**，状态为
`HostMismatch`，并写明"要求 BrimDeck …；当前是 …"。

普通模组不要引用内部程序集；若某项能力反复需要内部接口，请提出需求，让它成为稳定的注册表、事件或服务。

不要把当前工作目录当作模组根目录；业务数据通过 `Storage` 访问。打包复用 `build/ModulePackage.targets`，排除宿主和共享 SDK DLL。每次视图独立创建控件；程序集共享契约实例，私有业务库由模组自己提供。所有模组禁止引用桌面主程序集，随附示例遵守相同边界。

使用本页新增导航、可见性、字段元数据、文本／颜色或新主题入口时，清单声明 `apiMinor: 6`。不要把“主版本为 1”当成可以在 minor 1 使用任意后续 API。宿主拒绝未来 minor，平台仍处于实验阶段。

宿主详情显示数据／缓存占用，清空缓存保护活跃加载副本并保留业务数据；卸载确认后清理安装包、数据及缓存。失败项由持久化记录重试，旧目录隔离后才删除，不能影响后来重装的数据。没有安装记录的`modules-data` 目录（重装后可复用）**不会被自动删除**，只在管理页列出并交由用户确认清理。这些是宿主管理功能，尚未向模组开放通用业务缓存 API。

宿主提供[启动恢复与独立静态检查器](checker.md)。恢复决定先于模组代码，默认检查不执行模组。签名验证机制已实现，但随附信任密钥列表仍为空，尚无官方签发渠道；运行期无响应看门狗与后台任务 CPU 归因也未提供。普通异常边界和加载隔离不构成权限沙箱。不要在第三方文档中将规划中的能力写成已经可用。
