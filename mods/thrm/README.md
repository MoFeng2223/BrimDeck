# 散热器模组（thrm / Cooler）

散热器状态模组：CPU/GPU 温度与风扇转速。数据来自 THRM 桥——散热器控制软件在本机的 HTTP 服务
（`thrm-bridge.py`，`http://127.0.0.1:27391/sample`），宿主的系统监控快照不含温度与转速，桥不可省。

## 提供的界面

| 贡献 | 内容 |
|---|---|
| 页面 `thrm:cooler`（Order 150，620×250） | 三张弧形仪表卡：CPU 温度 / GPU 温度 / 风扇转速。弧线按读数占比填充；数值大字 + 小单位；温度卡副行为对应风扇转速，风扇卡副行为目标转速与挡位 |
| 持续活动 `thrm:readings` | 收起行三条读数（C / G / R 首字母表盘 + 数值），规格与内置系统监控读数同源；在「收起外观 → 小组件」中可开关（关掉后收起行回到内置读数） |
| 设置 `thrm:general` | 轮询间隔（1–10 秒，默认 2）、收起行读数开关（与组件开关同一存储） |

## 读数的分级配色（模组自有色，跨主题语义一致）

- 温度：≤70 绿 `#34C759`；70–90 橙 `#FF9F0A`；>90 红 `#FF3B30`
- 转速：≤1900 绿；1900–2700 蓝 `#0A84FF`；2700–3500 紫 `#AF52DE`；>3500 橙 `#FF9F0A`

分级色只出现在弧线/表盘上；数值、字母等文字一律走主题资源（`PanelPrimary`/`PanelSecondary`/`PanelTertiary`），
与内置读数一致，深浅主题自动跟随。表盘轨道用 `PanelRingTrack`，卡片底 `PanelFill`，弧线轨道 `PanelTrack`。

## 收起行表盘的规格来源

收起行是官方 `ModuleCompact` 视口（高 24 DIP × 行缩放），表盘完全按内置系统监控读数（`MonitorStrip` 的
dial）同规格复刻：直径 `Whole(16·scale)`、描边 `Max(1.2, Half(2·scale))`、字母 `7·scale`、开口在下
（自 225° 顺时针扫 270°）、中心下移 `size/32`、表盘与数值间距 `4·scale`、读数间距 `6·scale`、数值字号
`Half(11.5·scale)`。数值列宽按最宽样本（`100°` / `8888`）固定，读数不随数字跳动。

> 注：交接规格里的「环 14 DIP / 描边 2.2」是旧基座（完整圆环）时代的内置读数规格；本分支（#181 合入后）
> 的内置读数已改为开口向下的表盘（16 DIP），按 DEVLOG「以现实为准」原则采用现行规格。

## 实现要点

- **轮询**：`IModuleContext.Every(间隔, Poll)`；回调与 HTTP await 都回到 UI 线程（激活时捕获
  `SynchronizationContext` 兜底），样本投递与 `Changed` 事件始终在 UI 线程。`Interlocked` 防重入——桥变慢不会堆叠请求。
- **桥不可达**：返回 null，读数显示横线（—）；桥状态每次变化（断开/恢复）向模组诊断 `Report` 一次，不刷屏。
- **数据存储**：`preferences`（`ThermOptions`，JSON）。读损坏时报一次诊断并停用写入（不覆盖用户数据）。
- **首帧**：激活后立即拉取一次（激活发生在 UI 线程时）；否则等第一个间隔。
- 展开活动的控制条（320×76，仅当有视图调用 `ShowActivity` 时显示）为同三条读数的放大版 + 挡位文字。
