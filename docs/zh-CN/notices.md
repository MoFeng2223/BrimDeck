# 灵动提示

收到通知时，刘海、胶囊或指示条会从原位置连续展开，显示应用图标、标题和摘要；悬停约 0.25 秒或单击可查看详情，几秒后收回原形态。Windows 自己的横幅与通知中心默认保持不变，BrimDeck 只是同时显示一份；不想看到两份时，可以在“应用”页关闭单个应用的“系统横幅”（见下文）。全部在本机处理，不使用任何云端服务；连接了[邮箱](mail.md)时，只连接邮箱自己的服务器。

## 开启

灵动通知有两个开关，默认都打开；打开任意一个就接收通知，两个都关闭后不再接收：

- 设置 › 收起外观 › 灵动提示 › 提示新通知：收到通知时在刘海、胶囊或指示条上显示。
- 设置 › 展开外观 › 显示灵动通知：在展开面板中显示通知页。

两个开关互不影响：只打开通知页时，通知不会打扰你，只进入通知页；只打开“提示新通知”时，照常提示，只是没有通知页。

两个开关都属于配置。多块屏幕各自使用不同的配置时（设置 › 显示器与配置），每块屏幕按自己配置中的开关决定是否提示；几块屏幕使用同一份打开了“提示新通知”的配置时，都会提示。

刘海和胶囊上默认还有一个通知条，显示未读通知的条数：在 设置 › 收起外观 › 显示内容 中可以关闭“通知”，或和其他部件一起拖动排序。通知条需要通知页开启，没有未读通知时不显示，单击打开通知页，打开通知页后清零。默认在条数前显示最近几条未读通知的应用图标（最多 3 个）；在 设置 › 灵动提示 › 提示方式 › 通知条 中关闭“显示应用图标”后改为显示铃铛。指示条不显示通知条。

设置 › 灵动提示 下有两页：“提示方式”决定三个等级各自的样子，“应用”决定哪些应用提示、各用什么等级。开启后：

- 展开面板多出“通知历史”页（铃铛图标，有未看的通知时带红点；提示弹出过但你没有悬停、点开或在本页看到时，仍算未看），列出保留期内的通知，可查看正文、打开应用、复制、删除、暂停或清空。
  - 聊天应用（微信、QQ、钉钉、飞书、Teams、Slack、Telegram 等）同一标题的通知算作一个会话（聊天应用的标题就是会话名），在列表里只占一行，显示最新一条和条数；左侧显示最新一条，其余消息按完整内容列在下面（最多 20 条）。删除按钮删除整个会话的记录。邮件和其他应用的通知每条单独一行。
  - 单击左侧的图标或标题，或者“打开应用”按钮，会打开来源应用，并尽量直达这条通知对应的会话：BrimDeck 在你单击的那一刻只读地读取这一条通知的启动参数并交给应用，不保存、不写日志；读不到或应用不支持时只打开应用。
  - 复制按钮复制正文（一个会话有多条时按时间顺序全部复制）；在正文上单击右键可选择复制内容或复制标题。被遮住的验证码不会被复制，请使用“复制验证码”按钮。
- 通知的外观跟随[面板主题](themes.md)：与刘海、胶囊、指示条和展开面板使用同一套底色、渐变、扫描线、边缘、阴影或辉光与文字颜色。会发光的主题在通知到达时闪亮一次。应用颜色只用于图标旁的小圆点、进度环和首字母，并按主题自动调整到清晰可读。

## 到达时的动效

通知长到位之后，它的表面会像黏稠的液体一样动一下，再回到静止的形状：

- **胶囊**：两端反复甩出液滴再回流补满，上下边缘的辉光亮两次；与主体相连的颈部和液滴同主体共用一条连续的边界（描边、渐变、玻璃边缘都沿这一条走，里面没有线），断开后飞出去的小颗粒才有自己的边界。
- **刘海**：下方两个角鼓起，鼓包沿整圈轮廓行进（始终在轮廓外 5 DIP 以内），鼓包是主体轮廓的一部分，辉光沿着这条轮廓亮两次，越靠近肩部越细。
- **指示条**：不加任何额外的层。细线先向内回撤一点（最多 5 DIP），像压紧的弹簧，再随面板的开启弹簧展开成卡片；收起时卡片收回到线的位置后，会比线再多收一点（最多 7 DIP），再弹回线的长度。回撤与过冲的幅度随通知的分量缩放。

辉光在浅色和深色的桌面上都看得见：岛的背后是白色光晕，光晕之下垫着一层暗晕，岛的表面上沿边缘还有一圈同时闪亮的光。很长的胶囊或刘海上，液体的波纹由几道长而缓的涌动从两端传到中间。

播放多少动效由通知的提示等级决定，见下一节“提示等级”。辉光和液滴的颜色、边缘跟随[面板主题](themes.md)；像素方块主题用方块。动画关闭（BrimDeck 的设置或 Windows 的“动画效果”）或高对比度时不播放，通知与以前一样；胶囊与刘海的动效只在播放的约两秒里占用显示的帧，指示条的动效只是面板自己的那条动画，其余时间都不占用任何资源。额度提醒和切歌提示由岛自身表现，不播放这套动效。

通知跟随设置里的“缩放”（100% / 150%）：通知的大小、圆角、液滴、辉光和指示条的回撤与过冲都按缩放一起放大，与收起形态和展开的面板一致。

胶囊与刘海的液体动效来自维护者 MoFeng2223 提供的“胶囊通知动效”设计（<https://claude.ai/artifact/JU9bvJp5PPNY85vpGgUX6C>）；指示条的动效（回撤与过冲）、对各类通知和各个主题的适配是 BrimDeck 自己的实现。

## 提示等级

每条通知在岛上按一个等级显示：

| 等级 | 表现 |
|---|---|
| 1 · 文字 | 岛的形状不变，只把里面的内容换成提示文字。可以占用整个岛，也可以只占收起时某个部件（配额环、音乐、系统监控、时钟、文件中转、设备电量）的位置，其他部件照常显示。指示条显示不了文字，细线变亮一次。 |
| 2 · 闪动 | 在等级 1 的基础上，岛的边缘闪一下：“辉光”是背光亮两次，岛的轮廓不动；“灵动”再加上一节的液体波纹。指示条为呼吸光晕。 |
| 3 · 常驻 | 效果同等级 2，一直显示到处理为止，期间约每 3 秒重播一次。辉光可以换成其他颜色。 |

另有“只进通知页”：只进入通知历史，不在岛上显示。

每个等级的样子在 设置 › 灵动提示 › 提示方式 中设置：是否显示应用图标，等级 1 和 2 的停留时间，等级 2 和 3 的效果（辉光或灵动）与提示音，等级 3 的默认颜色。每个等级旁的“试一下”会发出一条示例提示。提示都占用整个岛，只有消息用 `--slot` 指定位置时才只替换其中一块。

某个应用需要不同的样子时，在 设置 › 灵动提示 › 应用 中单击它名称旁的箭头，打开“单独设置样子”；这个应用的提示就以自己的设置为准，优先于“提示方式”页和消息自己指定的样子。这里显示的是该应用当前等级的样子（等级为“按发送方”的程序列出三个等级）：等级 2 和 3 可以选辉光颜色和效果，等级 1 和 2 可以调停留时间，都可以选择是否显示应用图标。改变应用的等级后，这里随之换成新等级的样子。另外：

- 聊天应用（QQ、钉钉、飞书等）多一组“来电”，单独设置语音和视频来电的颜色、效果和图标；来电一直留在岛上，直到接听、挂断或展开面板。
- 时钟、日历、提醒类应用和命令行程序在等级不是 3 时，多一组闹钟、日程提醒或“等待处理”的样子，这些提示总是常驻。

这一项默认收起，一般用不到。

### 提示音

等级 2 和等级 3 可以各选一个提示音，等级 1 没有声音：

- 等级 2 的提示音在提示出现时响一次。同一条通知只响一次，两次提示音至少间隔 1 秒；超过“每 10 秒最多 3 次”而不再闪动的通知也不响。
- 等级 3 的提示音循环播放，首尾相接没有停顿，直到这条提示结束（展开面板、处理或关闭，默认最长 3 分钟）。循环播放期间不再播放其他提示音。
- 展开面板时到达的通知只显示在通知页，提示音响一次，等级 3 的也只播放一遍。有多个屏幕时，任一屏幕的面板展开期间，到达的通知不会在其他屏幕上提示。

内置的提示音由 BrimDeck 在播放时合成，等级 2 有水滴、叮、双音、琶音、轻敲、和弦，等级 3 有木琴、钟琴、晨曲、电话铃、嘀嘀。在下拉框中选择时会试听一次。

也可以使用自己的音频文件：在下拉框中选“导入文件…”，支持 WAV、MP3、M4A、AAC、FLAC、WMA，单个文件不超过 50 MB。文件会复制到数据文件夹的 `sounds` 中，两个等级都可以选用；“提示音”一栏的“打开文件夹”可以打开它，删除其中的文件即可移除。用于等级 2 时最多播放 10 秒；用于等级 3 时整个文件循环播放，WAV 文件可以做到首尾无缝，MP3 等压缩格式在首尾可能有极短的停顿。所选文件不存在时改用该等级的默认提示音。

Windows 应用的通知默认不播放 BrimDeck 的提示音，因为这些应用大多自带提示音，Windows 在关闭横幅后仍会播放。需要时打开“Windows 应用的通知也播放”；单独设置了样子的应用按它自己的提示音播放，不受这个开关影响。专注、演示、锁屏和暂停期间不播放提示音。音量在“提示音”一栏调整，调到 0 即全部静音。

等级按以下顺序确定，取最先符合的一条：

1. 你把该应用设为“只进通知页”。
2. 来电、正在响的闹钟、到点的倒计时、日程提醒，以及等待你处理的审批，为等级 3。
3. 你为该应用选择的等级。
4. 发送方指定的等级（命令行的 `-l`）。
5. 默认等级：等级 2，可在“提示方式”页改为等级 1 或 3。

常驻的提示在以下情况结束：

- 你单击它、鼠标停在上面打开通知页，或打开面板。有多个屏幕时，在任一屏幕打开面板，所有屏幕上的提示都会结束，各屏幕使用不同配置时也是如此。
- 来源已不再有这条通知：Windows 通知中心里已清除（BrimDeck 在下一次完整读取通知列表时发现）、闹钟或倒计时已停止、发送方用 `brim-notify close` 关闭，或用同一个 `-r` 键改发为其他等级。
- 显示满 3 分钟。

常驻的提示显示期间，其他通知照常进入通知历史并等待；等待超过 30 秒的普通通知不再补播。动画关闭（BrimDeck 的设置或 Windows 的“动画效果”）或高对比度时，各等级都只显示文字。

## 通知来源

| 来源 | 说明 | 默认 |
|---|---|---|
| Windows 应用通知 | 读取当前用户在 Windows 通知中心里的应用通知：来源、图标、时间和文字。默认接收所有应用的通知；不想接收的应用，在 设置 › 灵动提示 › 应用 中关闭它的“接收”开关：常用应用始终列在页面上方；其他应用单击“从通知记录添加”，从发过通知的应用中选择，这样添加的就是真正发送通知的那一个，移除后恢复默认。还没有发过通知的应用不会出现在列表中。不会读取应用内部的聊天消息；除非开启“允许 brim 读取和删除所有通知”并用 `brim notify remove` 删除，否则不会清除或修改通知中心。 | 开启 |
| 微信新消息 | 微信电脑版不发送 Windows 通知。“应用”页微信一行的“接收”开启时，它的任务栏图标闪烁会提示“微信 有新消息”；不读取消息内容和发送人。也可以改为读取消息内容，见下文。 | 开启 |
| brim-notify 命令 | Windows 上的 `BrimDeck.Notify.exe` 与 WSL 中的 `brim-notify` 主动发送提示。 | 开启 |
| WSL 桌面通知 | 所选发行版中 `notify-send` 等标准桌面通知（freedesktop D-Bus）。 | 关闭，按发行版单独开启 |
| 邮箱 | 已连接的邮箱中新到的邮件：发件人、主题和正文开头。在 设置 › 灵动提示 › 邮箱 中添加，见[邮箱](mail.md)。 | 未连接 |

### 常用聊天应用

BrimDeck 读取的是应用发给 Windows 的通知。聊天应用只有打开了桌面通知，消息才会出现在岛上。“应用”页的“常用应用”始终列出微信、QQ、钉钉和飞书，名称下方显示是否正在接收；还没有收到过通知，或在 Windows 中关闭了它的通知时，展开这一行可以看到要打开的设置。

| 应用 | 需要打开的设置 |
|---|---|
| QQ | 默认会发送 Windows 通知。没有提示时，确认 QQ 设置中的消息通知已开启，并在 Windows“设置 › 系统 › 通知”中允许 QQ 通知。 |
| 钉钉 | 单击左上角头像，进入“设置与隐私 › 通知”，在“桌面通知”中打开“消息桌面通知”；需要来电提示时打开“显示通话/会议邀请通知”。 |
| 飞书 | 单击左上角头像，进入“设置 › 通知”，勾选“新消息通知”和“横幅消息通知”，并选择在横幅中显示消息内容；不显示内容时，岛上只能看到“有新消息”一类的文字。 |
| 微信 | 电脑版不发送 Windows 通知，只能在任务栏图标闪烁时提示“有新消息”，读不到发送人和内容。 |

以上应用都还需要在 Windows“设置 › 系统 › 通知”中允许通知，并关闭“请勿打扰”。“应用”页里某个应用的“系统横幅”开关关闭后，Windows 不再弹出它的横幅，但通知仍进入通知中心，BrimDeck 照常读取。

### 微信：读取消息内容

微信电脑版不发送 Windows 通知，所以默认只在它的任务栏图标闪烁时提示“有新消息”。在 设置 › 灵动提示 › 应用 中展开微信一行，把“提示方式”从“任务栏闪烁”改为“读取消息内容”（选择时需要确认）后，BrimDeck 改为读取微信窗口里的聊天列表：

- 提示显示会话名和最新一条消息（群聊带发送人），同一会话的消息在通知页合并在一起；单击“打开应用”会打开微信并切到这个会话。
- 通知页可以直接回复：文字经微信自己的输入框和“发送”按钮发出。微信输入框里已有未发送的内容时不会发送。
- 微信窗口可以最小化，但不要关到托盘（单击窗口右上角的关闭）。关到托盘后读不到内容，只能按任务栏闪烁提示“有新消息”；重新打开窗口后自动恢复。
- 只能读到聊天列表中当前显示的会话，每个会话只有最新一条；连续收到多条时，中间的可能看不到。设为“消息免打扰”的会话只在有人 @ 你时提示，“公众号”“服务号”不提示，你正在使用微信时也不提示。在微信里读过的会话，对应的提示会标为已处理。

这项功能需要修改运行中的微信。微信只在检测到读屏软件时才开放界面信息，BrimDeck 把微信进程内存中表示“辅助功能已开启”的 1 个字节由 0 改为 1，之后通过 Windows 的界面自动化接口读取聊天列表；不修改微信的文件，不注入代码，不读取微信的数据库。改回“任务栏闪烁”或退出 BrimDeck 时改回 0。微信不支持这种用法：它可能使微信不稳定、在微信更新后失效，或导致账号受到限制，请自行判断是否开启。

### Windows：事件日志模式与轮询

BrimDeck 作为普通桌面程序运行时，Windows 不向它发送通知变化事件。Windows 的推送通知平台会在“应用程序和服务日志 › Microsoft › Windows › PushNotification-Platform › Operational”里为每条送达当前用户的通知记一条日志，普通用户也能订阅这份日志，所以 BrimDeck 默认使用**事件日志模式**：每条记录约 0.1 秒后（同批记录一起处理），BrimDeck 按记录中的编号只读取这一条通知，核对编号和应用身份一致后立即显示。这一步不等待完整列表读取，启动或唤醒后的第一次完整读取也不例外（唤醒后，在这次读取开始前记下的通知算作睡眠期间到达）。记录缺少可用编号或应用身份、通知读不到或属于其他应用时，改由完整读取处理。完整列表在后台读取：启动、获得授权或唤醒后各读一次（已有通知不再显示，睡眠期间到达的记为错过），每 60 秒做一次安全核对，并用来确认哪些通知已被清除。清除记录不说明是哪一条，所以这类读取最多每 30 秒一次；这条通知 Windows 暂时还读不到时（Windows 写日志略早于通知可读），先每 0.1 秒再读一次，最多 5 次；仍读不到，或记录、单条读取不可信时，约 1 秒内补读（已有清除记录在等时，随它一起读）。单条读取 5 秒内没有得到 Windows 回应（唤醒后见过）按失败处理：BrimDeck 重新取得通知监听器并完整读取列表。

这份日志被关闭（例如组策略）、无法订阅或连续出错时，自动改用**轮询模式**：每 2.5 秒检查是否有新通知（约 2.5 毫秒 CPU），每 15 秒完整读取一次列表；新通知通常在 0.2–2.6 秒内出现，空闲开销约为单个核心的 0.36%。设置页的状态行会显示当前是哪种模式。

早期测试版曾提供一个需要开发者模式的“身份包”（`BrimDeck.Notices`）来换取事件模式，现在已不再需要，安装器也不再管理它。注册过的话，可在 PowerShell 中运行 `Get-AppxPackage BrimDeck.Notices | Remove-AppxPackage` 删除；不再需要时也可以关掉开发者模式。

首次使用如果 Windows 尚未决定是否允许读取通知，设置页会显示“允许访问”按钮；被拒绝时可在 Windows 设置 › 隐私和安全性 › 通知中修改。

### Windows：应用自己的通知横幅

设置 › 灵动提示 › 应用 › 系统横幅（每个应用单独设置）。这个开关就是 Windows 设置 › 系统 › 通知 › 某个应用 › “显示通知横幅”，显示的是它现在的状态。关掉后，这个应用的通知不再从屏幕右下角弹出，只在岛上显示一次；通知照常进入通知中心，BrimDeck 照常读取。

- **改什么**：只改当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings\<应用 ID>` 下的 DWORD 值 `ShowBanner`：关闭时设为 0，打开时删除这一项（Windows 把没有这一项视为打开）。不需要管理员权限，也不重启任何程序。
- **长期有效**：和在 Windows 设置里修改一样，退出或卸载 BrimDeck 后仍然保持。在 Windows 设置里改过之后，回到 BrimDeck 设置窗口时开关会随之更新。
- **不能改的**：BrimDeck 自己；在 Windows 中关闭了通知的应用（开关显示为关闭且不可切换，名称下方会注明）。浏览器里各网站的通知共用浏览器的这项设置。
- **提示音**：只关横幅，不关提示音。实测（Windows 11 26300）`ShowBanner` 为 0 时横幅不再弹出，提示音照常播放；需要静音的应用请在 Windows 设置里关闭它的“播放声音”。
- **注意**：`ShowBanner` 不在 Windows 的公开文档里，以后的 Windows 版本可能不再读取它。BrimDeck 写入后会读回核对，Windows 没有保留的会在应用名称下方提示；如果关闭后仍看到横幅，请在 Windows 设置 › 系统 › 通知 中逐个关闭。
- **早期版本留下的改动**：早期版本只在 BrimDeck 运行时关闭横幅，并把原来的状态记在 `%LOCALAPPDATA%\BrimDeck\notice-banners.json`。这个文件还在时，BrimDeck 启动和卸载时会按记录恢复，恢复完成后删除它。

### Windows：应用的名称、图标和分类

Windows 通知里的应用标识有时看不出是哪个应用，BrimDeck 会这样处理：

- **Edge 安装的网页应用**（如 WhatsApp 网页版、Facebook）：按网站命名，例如“WhatsApp”，不显示为 Microsoft Edge；不同网站是不同的应用，可以分别设置规则。正文末尾重复的网址会去掉。
- **Chrome 等浏览器里网站的推送**：浏览器会在最后一行附上网站地址。BrimDeck 去掉这一行，并按网站区分来源，例如“Gmail · Google Chrome”，这样可以只添加或单独设置某个网站。只有两行文字的通知保持原样。
- **没有开始菜单快捷方式的桌面程序**：使用它注册的名称和图标（注册表当前用户或本机的 `Software\Classes\AppUserModelId`，例如 Windows 安全中心；图标只取本机文件）。
- **Windows 不提供应用信息的通知**：从 Windows 的通知数据库中查出这条通知所属的应用标识，与 Windows 通知中心一样，以标识作为名称显示（例如“YaluDevAgent”），可以照常单独设置。仍无法确定应用的通知显示为“未知应用”，图标显示首字母，不能打开来源应用，也不能单独设置。
- **Windows 没给名称的常见程序**：哔哩哔哩、钉钉、Gemini、经典版 Outlook 等按 BrimDeck 内置的名称显示；Squirrel 安装的 Electron 程序（如 Discord、Slack）显示为程序名。
- **老式托盘程序的气泡提醒**：Windows 没有给出名称时显示为“托盘程序”，不再显示一串数字；只有程序路径的桌面程序显示为程序名。
- **默认分类**：Windows 通知不带分类。Claude、Codex（ChatGPT）、Gemini 桌面版和 Cursor 的通知标为“任务”；Windows 系统提醒、Windows 安全中心、NVIDIA App、Adobe Creative Cloud、Clash Party/Clash Verge、截图工具、联想和英特尔的工具等标为“提示”；聊天、邮件和浏览器保持“消息”。
- **来电**：聊天应用（QQ、微信、Teams、WhatsApp、Discord 等）和手机连接的通知如果是语音/视频通话邀请（“邀请你进行语音通话”“Incoming call”“is calling you”等），显示来电标记，并像闹钟一样立即弹出（该应用设为“只进通知页”时除外）；“未接来电”不算。
- **被替换的通知**：应用用同一条通知更新内容时（比如 QQ 把新消息合并成一条），Windows 会删掉旧通知、加入新通知。如果两者来自同一应用、标题相同，并且在同一次读取中出现，BrimDeck 会更新原来那条提示，不会留下两条。
- **emoji 的显示**：WPF 不支持彩色字体，emoji 显示为单色；由多个 emoji 组合成的序列（如家庭、彩虹旗）可能显示为方框，国旗显示为两个字母。这是平台限制，文字本身不受影响。

### WSL

在“WSL（默认关闭）”下打开某个发行版后，BrimDeck 会：

- 把通知代理复制到该发行版默认用户的 `~/.local/share/brimdeck/brimdeck-agent`，并写入 `bridge.json` 与版本记录。代理分别为 x64 与 ARM64 构建，各有 glibc 版（Ubuntu、Debian、Fedora 等大多数发行版）和 musl 版（Alpine）；BrimDeck 按发行版的 `uname -m` 和程序加载器选择。都不能运行的发行版（32 位 ARM、RISC-V，或 C 库不在标准位置）会在设置中显示为不受支持，30 分钟内不再重试；
- 添加 `~/.local/bin/brim-notify`。只有内容与 BrimDeck 写入的完全一致时才会更新它；同名的其他文件或符号链接一律保持不动，并在设置中提示冲突（此时可直接用 `~/.local/share/brimdeck/brimdeck-agent notify`）。所有文件都先写到新建的临时文件再改名替换，不会顺着符号链接写到别处；
- 只在发行版**已运行**时通过 `wsl.exe` 启动代理，绝不为了接收通知而启动发行版，也不修改 WSL 配置或替换系统的 `notify-send`。WSL 1 与 WSL 2 发行版都支持；
- 代理本身是一个 `wsl.exe` 会话，它运行时 WSL 不会自动停止发行版和虚拟机。因此代理每分钟检查一次：发行版中该用户除代理自身、WSL 的 init/中继进程和会话组件（`systemd --user`、`(sd-pam)`、`dbus-daemon`/`dbus-broker`）以外已没有任何进程（终端、后台任务都算在内），并且持续 5 分钟，代理就自行退出，让 WSL 照常停止发行版、释放内存。设置中显示为“代理已退出”。之后发行版停止、再次运行时，代理自动重新接入；如果发行版因为其他原因一直没有停止，BrimDeck 最多每 30 分钟再启动一次代理，不会反复重启。

代理按 `DBUS_SESSION_BUS_ADDRESS`、`$XDG_RUNTIME_DIR/bus`、`/run/user/<uid>/bus`（后两者须属于该用户）、`~/.dbus/session-bus/<machine-id>-<显示编号>`（无 systemd 时由 X11 自动启动的总线）的顺序查找会话总线；暂时没有总线时每 3 秒检查一次。

代理按会话总线的情况自动选择：

| 情况 | 处理方式 |
|---|---|
| 没有通知服务 | 代理成为该会话的标准通知服务，应用的按钮会显示在详情中并回传给应用 |
| 已有通知服务且允许监视 | 旁路观察，不替换原服务；原服务的按钮不提供 |
| 已有通知服务且不允许监视 | 显示限制；`brim-notify` 仍可用 |
| 没有会话总线 | 显示限制；`brim-notify` 仍可用 |

作为通知服务时，代理声明 `body-markup`：正文中的标记按纯文本显示（去掉标签、解码 `&lt;` 等），标题始终原样显示。带 `x-canonical-private-synchronous`、`synchronous` 或 `x-dunst-stack-tag` 提示的通知（音量、亮度等）按同一应用、同一标签更新同一条提示；带 `transient` 提示的通知照常显示，但不保存到已保存的通知中。图标是 `/usr/share/icons` 或 `/usr/share/pixmaps` 内的符号链接、且链接一直指向这两个目录内时，按实际文件显示（Debian/Ubuntu 的主题图标多为链接）；其他符号链接仍不读取。

移除：在设置中关闭该发行版，然后在发行版中删除 `~/.local/share/brimdeck` 与 `~/.local/bin/brim-notify`。

## brim 命令

`brim` 是 BrimDeck 的命令行，提示是它的第一组命令。Windows 上为安装目录中的 `brim.exe`，已开启的 WSL 发行版中为 `~/.local/bin/brim`。它用一次启动一次，把消息交给正在运行的 BrimDeck 后退出；BrimDeck 没有运行时约 2 秒后以退出码 3 结束，不会代为启动 BrimDeck。

安装程序会把安装目录加入 PATH（为当前用户安装时改当前用户的 PATH，为所有用户安装时改系统的 PATH），所以在新打开的终端里可以直接输入 `brim`；卸载时移除这一项，PATH 中的其他内容不动。安装前已经打开的终端需要重新打开。免安装版不修改 PATH。PATH 中没有 BrimDeck 的目录时，终端、脚本和 AI 工具的钩子找不到 `brim`，只能用完整路径调用（“复制命令行路径”可取得 `brim.exe` 的完整路径）。这时 设置 › 灵动提示 › 应用 › 命令行与程序 会显示“brim 命令未加入 PATH”：点“加入 PATH”为当前用户加入，修改失败时同一处会说明原因；标题旁的说明里有手动添加的步骤（开始菜单搜索“环境变量”›“编辑账户的环境变量”› 用户变量中的 Path ›“编辑”›“新建”），“复制目录”可复制要填入的目录。

```text
# 显示一条提示
brim notify send "构建完成" "测试已通过"
# 指定来源和等级（0 只进通知页，1 文字，2 闪动，3 常驻）
brim notify send "部署完成" -s 部署脚本 -l 2
# 同一 -k 键更新同一条提示（任务进度）
brim notify send "部署中" -k deploy --progress 40
# 常驻到处理为止，之后用 close 关闭
brim notify send "等待确认部署" -k deploy -l 3
brim notify close deploy
# 带按钮并等待选择：输出 allow 或 deny
brim notify send "请求运行命令" "dotnet test" -s "Claude Code" -k perm --action allow=允许 --action deny=拒绝 --timeout 5m
# 复制与打开按钮由 BrimDeck 处理，不需要等待
brim notify send "GitHub 验证码" "482913" --copy "复制=482913" --open "打开网页=https://github.com/login"
# 等级 1 的提示只占音乐那一块，且不进通知历史
brim notify send "已切换到耳机" -l 1 --slot music --no-history
# 运行命令，结束后显示结果（退出码与用时）
brim run -- dotnet test
# 检查 BrimDeck 是否在接收
brim status
```

`brim notify send` 的选项：

| 选项 | 作用 |
|---|---|
| `-b/--body 文字` | 正文，也可以写作第二个参数 |
| `-s/--source 名称` | 来源名称；也可以用环境变量 `BRIM_SOURCE` 为脚本或钩子统一指定。不给时为 `brim`。设置 › 灵动提示 › 应用 里按这个名称列出，每个来源可单独设置 |
| `--context 文字` | 来源旁的补充说明，例如项目、分支或会话名 |
| `-l/--level 等级` | `silent`、`plain`、`flash`、`persistent`，或 `0`–`3`。你为该来源选择的等级优先；每个等级的样子在 设置 › 灵动提示 › 提示方式 中决定 |
| `-c/--category 分类` | `message`、`task`、`success`、`warning`、`error`、`info`。常驻的提示为 `warning`、`error`、`success` 时辉光分别为橙色、红色、绿色 |
| `--glow "#RRGGBB"` | 常驻提示的辉光颜色，优先于分类的颜色和设置中的默认颜色 |
| `--slot 位置` | 等级 1 的提示显示在哪一块：`island`（整个岛）、`usage`、`music`、`monitor`、`clock`、`transfer`、`devices`。不指定时占整个岛；收起形态里没有这一块或形态为指示条时占整个岛 |
| `--align 位置` | `left`、`center`、`right`，图标和文字在岛上的位置 |
| `-i/--icon 路径` | 本机图标文件；`none` 不显示图标。相对路径从当前目录算起 |
| `--image 路径` | 头像或图片，显示在图标的位置 |
| `-k/--key 键` | 同一键更新同一条提示，`brim notify close 键` 关闭它（来源须与发送时一致） |
| `--id 标识` | 重试时去重 |
| `--progress N` | 任务进度，0 到 100 |
| `--action 键=文字` | 按钮：点击后 `brim` 把这个键写到标准输出并退出。带这种按钮时自动等待；第一个为主要按钮 |
| `--copy 文字=内容` | 按钮：点击后复制内容 |
| `--open 文字=目标` | 按钮：点击后打开网址（http、https）、本机文件或文件夹，或 `app:<应用 ID>`。从 WSL 中只能打开网址 |
| `--wait` | 等到提示被处理、关闭或超时再退出 |
| `--timeout 时长` | 常驻提示最长显示多久，例如 `5m`；默认 3 分钟，最长 30 分钟 |
| `--no-history` | 只在岛上显示，不进通知历史 |
| `--json 文件` | 从文件读取整条消息（JSON），`-` 表示标准输入；命令行上给出的选项覆盖其中的值 |

你在 设置 › 灵动提示 › 应用 中为某个来源单独设置了样子（名称旁的箭头）时，以你的设置为准：`--glow`、分类的颜色和 `--icon none` 对这个来源不再起作用。

按钮：

- 最多 4 个。岛上最多显示 2 个，其余在通知页中。岛的大小不变，默认宽度的岛通常只放得下主要的那一个；按钮文字建议不超过 4 个汉字，过长会被截断。
- 岛上是否显示按钮由 BrimDeck 决定：设置为点击展开，或悬停展开的延迟不少于 0.5 秒时显示；悬停立即展开时不显示，因为鼠标移上去面板就已展开，按钮在通知页里。指示条形态和只占一块的提示不显示按钮。
- BrimDeck 不执行任何命令。`--open` 的目标如果是程序、脚本、快捷方式这类会运行的文件，只在资源管理器中选中它，不运行。需要执行操作时，用 `--action` 等待结果，由你的脚本自己执行。
- 识别到验证码（需打开“遮住验证码”）或可以打开来源应用时，BrimDeck 会自己补上“复制验证码”“打开”按钮。

等待结果（`--wait`，或带 `--action`）：

- 命令保持连接，直到你点了按钮、关闭或删除了这条提示、它超时，或发送方用 `close` 关闭了它。
- 这类提示始终按常驻显示，并且一定进入通知页，除非你把该来源设为“只进通知页”或“不提示”。
- 提前结束命令（例如 Ctrl+C）会同时关闭这条提示。

退出码：

| 退出码 | 含义 |
|---|---|
| 0 | 已送达（或被你的规则设为不显示）；等待时表示点了某个按钮，按钮的键在标准输出中 |
| 1 | 用法错误（包括按 BrimDeck 的长度上限截短后仍超过 64 KB 的消息） |
| 2 | 被 BrimDeck 拒绝（包括 `close`、`stop`、`remove` 找不到这个键或编号） |
| 3 | BrimDeck 未运行、灵动提示已关闭，或没有及时回复（此时提示仍可能显示） |
| 4 | 等待时：提示被关闭或删除，没有选择；或该来源被设为“不提示” |
| 5 | 等待时：超时 |

`brim run` 返回所运行程序自己的退出码。标题和正文在发送前就按 BrimDeck 的上限截短。钩子脚本遇到退出码 3 时应回到原有的流程，不要一直等待。

消息的 JSON 字段与命令行选项对应，例如：

```json
{
  "title": "请求运行命令", "body": "dotnet test",
  "appName": "Claude Code", "context": "BrimDeck · mofeng",
  "level": "persistent", "category": "warning", "replaceId": "perm",
  "actions": [
    { "key": "allow", "label": "允许", "style": "primary" },
    { "key": "deny", "label": "拒绝" },
    { "key": "copy", "label": "复制命令", "type": "copy", "value": "dotnet test" }
  ],
  "timeoutMs": 300000
}
```

### 查看与删除通知

`brim notify list` 列出通知页中的通知，每条带一个编号；`brim notify close` 和 `brim notify remove` 可以用这个编号（`--notice`）或发送时的键（`-k`）找到通知。

```text
# 列出通知（-s 只看某个来源，--json 输出 JSON）
brim notify list
brim notify list --json -s 部署脚本
# 关闭：岛上的提示结束，通知页里保留这条记录
brim notify close --notice 5112c23c8fcd4de886842687835782fa
# 删除：从通知页中删除，与在通知页里点删除相同
brim notify remove deploy -s 部署脚本
brim notify remove --notice 5112c23c8fcd4de886842687835782fa
```

- 能看到和删除哪些通知：默认只有 `brim` 和其他程序发来的通知。在 设置 › 灵动提示 › 应用 › 兼容性 中打开“允许 brim 读取和删除所有通知”（默认关闭）后，包括 Windows 应用、WSL 桌面通知在内的所有通知都会列出，也都可以删除。本机运行的任何程序都能使用 `brim`，开启前请确认可以让它们读到这些内容。
- 删除 Windows 应用的通知时，同时从 Windows 通知中心删除；Windows 中的这条通知已经变化或无法删除时，只删除 BrimDeck 的记录，`brim` 会给出提示，退出码仍为 0。WSL 桌面通知只删除 BrimDeck 的记录。
- 用键删除时，来源须与发送时一致；用编号删除时不看来源。`close` 用编号时只能关闭命令行和程序发来的通知。
- 删除一条正在等待回复（`--wait` 或带 `--action`）的通知时，等待的命令按“关闭，没有选择”结束，退出码为 4。
- 打开了“遮住验证码”时，列出的标题和正文中的验证码同样用圆点遮住。
- `list --json` 输出 `{"scope": ..., "notices": [...]}`：`scope` 为 `cli`（只含命令行和程序的通知）或 `all`；每条通知有 `id`、`origin`（`windows`、`taskbar`、`wsl`、`cli`、`brimdeck`）、`source`、`key`、`title`、`body`、`context`、`category`、`kind`、`receivedAt`，以及 `unread`（未读）、`shown`（正在岛上显示）、`waiting`（发送方在等待回复）、`closed`（来源已关闭或清除）。

### 旧名称 brim-notify

`BrimDeck.Notify.exe` 与 WSL 中的 `brim-notify` 仍然保留，写法与以前相同（`brim-notify "标题"`、`brim-notify close 键`、`brim-notify timer 25m` 等），选项与 `brim` 通用。新脚本请使用 `brim`。

## 时间类通知

闹钟、计时、倒计时、邮件和日程提醒会自动识别，按种类显示：

| 种类 | 来源 | 显示 |
|---|---|---|
| 闹钟 | Windows 时钟的闹钟、计时器结束、专注时段结束的系统通知 | 高优先级；可“打开应用”回到时钟 |
| 计时进行中（秒表） | `brim-notify stopwatch` | 实时显示“已计时 12:03”，可停止 |
| 倒计时 | `brim-notify timer` | 实时显示“还剩 24:59”和进度环；到点时再次弹出（高优先级），可取消或“5 分钟后再提醒” |
| 闹钟 | Microsoft To Do 的任务提醒 | 同上 |
| 邮件 | Outlook（新版和经典版）、邮件和日历、Thunderbird、Foxmail 等的新邮件通知；浏览器里网页邮箱（Gmail、Outlook 网页版、QQ 邮箱、网易邮箱等）的通知；WSL 中带 `email` 类别的桌面通知；已连接的邮箱（见[邮箱](mail.md)） | 普通通知 |
| 日程 | Microsoft 365 日历、邮件和日历的日程提醒；Outlook 中像提醒的通知（“15 分钟后”“现在”或以“下午3:00 - 下午3:30”开头的一行）；Teams 的会议提醒和“会议已开始”；Google 日历网页版的提醒，网页邮箱中像提醒的通知；`brim-notify event` | 高优先级，显示“14 分钟后开始”“进行中”；`brim-notify event` 由 BrimDeck 自己在开始前提醒 |

- 识别依据是应用的 ID（AUMID）和通知文字，只在本机内存中判断，不保存原始通知，不读取邮箱或日历（你在“邮箱”页连接的邮箱除外，见[邮箱](mail.md)）。识别属于启发式：Outlook、Teams 的提醒格式随版本和语言变化，未识别时按普通通知显示。
- 时钟、Outlook、To Do、Teams、日历等应用的提醒默认都会显示；不想接收的，在 设置 › 灵动提示 › 应用 中关闭它的“接收”开关。
- 闹钟、倒计时到点和日程提醒为高优先级，按等级 3 显示，不受“每 10 秒最多 3 次”的限制，但同一来源每分钟最多响 3 次（每个 Windows 应用各算一份，brim-notify 和 WSL 应用各共用一份），其余排队等待，所以脚本一次设下的大量计时器不会挡住其他应用的闹钟；你把该应用设为“只进通知页”时照常不弹出。锁屏、演示和暂停期间同样只计入汇总。开始时间已过去 10 分钟以上才补录的日程按普通通知记录。电脑睡眠期间到达的 Windows 通知在唤醒后只记录、不弹出，但其中 10 分钟内刚发出、或日程正好在前后 10 分钟内开始的提醒仍会照常提醒。未提醒的计时器、日程和正在运行的秒表最多保留 200 个；超出时，从持有最多的那个来源中移除 BrimDeck 最早收到的一个（并记入日志），其他应用的提醒不受影响。
- 实时文字由一个共享的每秒节拍刷新，只在岛上或“通知历史”页正显示进行中的计时时运行；倒计时和日程由 BrimDeck 按时钟计算，休眠唤醒、修改系统时间后会立即重新计算。错过超过 10 分钟的提醒（电脑休眠、BrimDeck 未运行）不再弹出，只在列表中显示“已于 15:30 结束”。
- 限制：Windows 不对外提供时钟应用里正在运行的计时器、秒表和闹钟列表，也不提供系统通知上的“贪睡/关闭”按钮，所以时钟的闹钟只能在响起时显示，不能代为贪睡；需要在岛上看计时可用 `brim-notify timer`。日程同步（直接读取 Outlook 或 Windows 日历）尚未支持，目前依靠应用自己发出的提醒通知。

```text
# 倒计时 25 分钟，到点提醒（也可 1h30m、90s）
brim-notify timer 25m "番茄"
# 倒计时到 15:30
brim-notify timer --at 15:30 "开会"
# 秒表，显示已用时间
brim-notify stopwatch "构建" -r build
# 停止秒表，或取消倒计时、日程（与发送时的 -s 来源一致）
brim-notify stop build
# 日程：开始前 10 分钟和开始时提醒
brim-notify event "周会" --at 15:00 --remind 10m --ends 16:00
# 把普通提示标为邮件（或 alarm）
brim-notify "新邮件" --kind mail
```

- 时间写法：`15:30`（下一次出现的 15:30）、`YYYY-MM-DD 15:30` 这样的日期加时间，按 **Windows 的时区**理解（WSL 发行版的时区不同也一样）；也可写带时区的 ISO 8601，如 `YYYY-MM-DDT15:30:00+08:00`。夏令时跳过的时刻顺延到跳变后，重复的时刻取较早一次。
- 时长写法：`90s`、`25m`、`1h30m`、`2d`；倒计时 1 秒到 31 天，提前提醒最多 7 天，时刻须在 1 天前到 1 年内。相对时长从 BrimDeck 收到时开始算，不依赖 WSL 的时钟。
- 没有给 `-r` 时会生成一个键并打印到标准输出，可用 `brim-notify stop 键` 结束；给定 `-r` 再发一次会重新开始。
- 未完成的倒计时和日程在通知历史的保留时间不是“退出时清空”时会在重启后继续；还没提醒的日程不受保留时长清理。

## 显示规则

- 提示不会抢占输入焦点，不会在展开面板或你正在操作的详情上弹出；面板展开时只在铃铛上增加红点。
- 等级 1 和 2 默认停留 6 秒，可在“提示方式”页分别修改；悬停、查看详情或用键盘操作时暂停计时。
- 同一会话（同一应用、同一标题，例如 QQ 通知的标题是会话名；没有标题时按应用）的新通知，只要岛上正显示或正等待着这个会话的一条，就合并进去：显示最新的文字和数量。一条合并通知最多停留两倍时长。
- 其他会话的新通知立即显示：岛上的通知已显示满 1.5 秒时直接接替，未满时等到满 1.5 秒（闹钟、来电不等）。被接替的通知不再补播，仍在通知历史中。同时等待的多条按到达先后依次接替。岛上是高优先级通知时，普通通知等它结束；常驻的提示和鼠标停留的通知不会被接替。等待超过 30 秒的普通通知不再补播。
- 每 10 秒内最多 3 条通知播放动效；超出的通知照常立即显示，但按等级 1 显示（不发光、不起波纹）。
- 图标和文字放得下时居中（发送方可指定靠左或靠右）；放不下时从左开始并滚动。
- brim-notify 和 WSL 的通知按发送方写下它的时间判断新旧：发出时已等待超过 30 秒（高优先级 5 分钟）的消息只记入通知历史并标为未读，不再弹出。等待时间由发送方用自己的时钟计算，WSL 与 Windows 时钟不一致也不会误判；时间类通知按各自的提醒时间处理。同一条消息（相同事件 ID）在 BrimDeck 重启后再次送达，只要通知历史中还有它，就不会重复记录或弹出。
- 用 `-r` 更新的通知按最新一条消息计时：弹出时显示“刚刚”，而不是被替换的旧通知的时间。
- 通知到达时如果鼠标正停在岛上，不会自动展开详情，需要移开再移回或单击。
- 单击岛上的提示打开通知页，并把这条提示放在最前面。
- 优先级：你正在操作的内容 > 高优先级通知 > 普通通知 > 配额提醒 > 切歌提示。闹钟、倒计时到点和日程提醒属于高优先级（见“时间类通知”）。
- 锁屏、切换用户、手动隐藏、全屏隐藏规则生效时不显示内容；Windows 专注会话、演示模式和 BrimDeck 自己的“暂停提醒”期间不弹出，结束后只显示一次数量汇总。Windows 单独的“请勿打扰”开关没有公开接口，无法识别，可使用 BrimDeck 的暂停。
- 多显示器：每块屏幕按它使用的配置中“提示新通知”是否打开决定是否提示。该屏幕的面板被隐藏时，通知留在通知历史中，不会跳到其他屏幕。同一条通知在每块提示的屏幕上各显示一次，频率只计一次；在任一屏幕上处理了它（单击、打开通知页），其他屏幕上的同一条一并结束。
- 设置 › 快捷键 › 打开灵动提示（默认不设置）：有提示时打开详情并可用键盘操作（Tab 切换、Enter 确认、Esc 关闭）；没有提示时打开通知历史。

## 隐私

- 通知历史默认保存 24 小时、最多 500 条，使用 Windows 为当前用户提供的加密（DPAPI）写入 BrimDeck 安装目录的 `notices` 文件夹（只对当前用户开放；安装目录不可写时改存 `%LOCALAPPDATA%\BrimDeck\notices`）；保留时间可选退出时清空（仅在内存中保留，此时应用图标也不写入磁盘）、1 小时、1 天、3 天或 7 天，也可以一键清空。提醒响起或秒表停止后，从这一刻起重新计算保留时间。
- 保存通知的文件夹是链接、不归当前用户所有，或者其他账户也能改动其中的文件时不会读写，设置页会说明原因；后一种情况可以在设置页点“仅限本人访问”，把文件夹设为只对当前用户和系统开放。每次读写前都会确认文件夹和 `notices.dat` 都不是链接，`notices.dat` 是链接时不会读取它。保存的文件暂时无法访问（被占用、所在的盘或网络位置不可用）时，BrimDeck 稍后自动重试，在此之前不会写入，以免覆盖原有记录；这段时间里删除或清空的通知，在文件读回后也不会再出现。文件确实损坏时提示清空重建；当前账户没有读取权限（例如文件由以管理员身份运行的 BrimDeck 创建）时，可以重试，也可以清空重建。每次保存都先把新文件写入磁盘再替换旧文件，断电不会留下损坏的文件。
- 删除或清空只删除 BrimDeck 自己的记录，不会通知来源应用（例外：开启“允许 brim 读取和删除所有通知”后，用 `brim notify remove` 删除 Windows 应用的通知会同时从 Windows 通知中心删除）；只有在提示上点关闭或按 Esc，才会把 WSL 桌面通知按“用户关闭”回报给来源（与关闭桌面通知气泡一致）。关闭灵动提示或清空时，正在显示和排队等待的提示会一并取消。
- 不保存原始通知内容、附件或头像；应用图标只来自 Windows 或本机文件，不下载任何网络图片。网络路径、链接或快捷方式指向的图标会被拒绝。
- 诊断日志 `notices.log` 只记录错误类型、错误码与调用位置，不含标题和正文。
- 本地通道只允许当前用户在本机连接（命名管道，拒绝网络访问）；通知内容只作为文字显示，不会作为命令执行，也不会打开其中的链接。
- 所有 Windows 应用默认都会提示；常用应用和从通知记录添加到“应用”页的应用可以关闭接收、设置等级（包括“只进通知页”）、开关它在 Windows 中的系统横幅，以及单独的样子。命令行和程序的来源第一次发送后自动列出，可以设为“不提示”。
- 验证码（设置 › 灵动提示 › 提示方式 › 遮住验证码，默认关闭）：打开后，BrimDeck 在本机识别通知标题和正文里的验证码（中英文关键词加数字或短字母数字；订单号、金额、电话、日期、链接不算），在灵动提示和通知页里用圆点遮住，读屏软件只会读到“验证码已隐藏”；通知页给出“复制验证码”按钮。识别不联网，不写日志；只有点这个按钮才写入剪贴板，并要求 Windows 不把它收入剪贴板历史、不同步到云端，60 秒后如果剪贴板里仍是这个验证码就清空（已复制了别的内容则不动）。保存到加密通知历史里的也是遮住的文字，所以重启后无法再复制；关闭开关即恢复原样。验证码的识别规则移植自小唐的岛仔（MIT，见 ThirdPartyNotices.txt），宁可漏识别也不误遮。

## 兼容性（实测）

| 场景 | 结果 |
|---|---|
| Windows 11（26300） | 可读取通知快照；变化事件不可用，事件日志模式按 TrackingId 单条读取，完整列表用于周期与删除对账；日志关闭时轮询 |
| Windows 通知中的图标 | 打包应用可取得图标；缺失时显示应用首字母 |
| 打开来源应用 | 打包应用通过应用列表启动；桌面应用通过开始菜单注册的应用 ID 启动；不支持时在详情中说明 |
| WSL Ubuntu 26.04（systemd 会话总线，无通知服务） | 代理成为通知服务；gdbus/notify-send 通知显示；按钮回传 `ActionInvoked` 与 `NotificationClosed` |
| WSL 已有通知服务 | 旁路观察，正确取得通知 ID 与关闭事件 |
| 多显示器（含负坐标、125% 缩放副屏） | 在前台窗口所在显示器弹出，位置与缩放正确 |
| 8 套内置主题 × 刘海、胶囊、指示条 | 外观逐一核对 |

未实测的情况（如锁屏中的真实行为）以设计为准，可能需要在你的环境中确认。
