# 输入法切换

在设置中打开“输入法”，启用模块，并在“仅通知”和“接管切换”之间选择工作模式。已有配置继续使用接管模式；切换模式会保留录制的快捷键、参与名单和顺序。

## 仅通知

沿用 Windows 或输入法原来的快捷键与切换菜单。灵动岛只显示真实启用项变化后的短暂结果，不显示选择列表，也不限制 Windows 可以切换到哪些输入法。此模式不创建键盘快捷键服务，不主动激活输入法；录制与排序控件会隐藏。

观察器复用目标线程的只读查询，每约 250 毫秒检查前台输入法；变化需稳定至少 150 毫秒，且切换修饰键已松开后才提示。首次读取不提示，相同状态不重复提示，快速切换合并为稳定后的结果。切换应用后实际生效的输入法变化也会被识别。普通面板展开时跳过通知，避免打断正在查看的内容。

无法读取的窗口暂时跳过并退避重试，不会根据按键猜测切换成功。关闭模块、切换模式或锁屏会清除当前观察状态。

## 接管切换

选择希望参与循环的项目。可只开启微信输入法与小狼毫。拖动行前的手柄调整顺序，或使用上移、下移按钮；这些设置只在接管模式生效。

默认按住 **Win**，点按 **空格**预选下一项；继续点按会按保存的顺序循环。松开最后一个 Win 键后启用预选项。按住期间只预选，不反复切换系统输入法；长按空格不连续跳项。

点击“切换快捷键”开始录制，按下并松开组合键后自动保存。支持 `Ctrl+Space`、`Ctrl+Shift+Space`、`Alt+K` 等，也支持只有修饰键的 `Ctrl+Shift`。以 `Ctrl+Shift` 为例：按住 Ctrl，点按 Shift 循环，松开 Ctrl 确认；反向按住 Shift、点按 Ctrl 也可以。多修饰键加普通按键的组合在任一必需的修饰键松开时确认。列表底部会显示当前组合的操作提示。

录制期间不执行切换；按 Esc、点击其他控件、离开设置窗口或等待 30 秒可取消，保留原组合。清除快捷键会释放接管，按钮“恢复 Win + 空格”恢复默认。与隐藏/显示、展开快捷键重复时会提示并拒绝保存；普通字符、单独修饰键和部分系统保留组合不接受。

高亮及右侧箭头表示即将启用的项，“已启用”表示本轮开始时的真实当前项。原输入应用保留焦点。确认成功后显示约 650 毫秒反馈；空间较小时只显示成功标记。之后恢复时钟、音乐或用量内容，不常驻显示输入法状态。

切换列表纵向一次展示所有参与项，不滚动。每行统一高度、图标尺寸和名称/状态列宽，切换时只移动高亮；项目较多或屏幕较小时，整张列表统一缩放以完整放入可用空间。展开期间不使用尺寸回弹，原收起框的尺寸保持到本轮反馈结束，输入法名称长短不会撑大组件。

已确认的结果在收起过程中渐入，收起完成后完整停留约 650 毫秒，再用原页面过渡淡回原内容。指示条模式直接收为结果胶囊，反馈结束后恢复指示条，避免先缩为线条再突然放大的二次变形。关闭动效时所有状态即时完成。

取消参与只影响 BrimDeck 的循环列表，不卸载或关闭 Windows 中的输入法。不可用的已选项保留设置并跳过，新安装的项目不会自动参与。没有可用项、面板隐藏或目标窗口无法接管时，Windows 继续处理原快捷键。停用模块或退出 BrimDeck 会释放快捷键。

## 兼容范围

首版支持 Windows 10 2004 及以上系统中的常规 x64 桌面应用。32 位应用、权限高于 BrimDeck 的窗口、受保护应用和原生组件无法访问的窗口交由 Windows 处理，设置页会保留最近一次接管失败的提示。无需为了切换而以管理员身份运行 BrimDeck。

输入法枚举使用 Windows TSF。一个小型原生组件通过短暂的、仅针对目标线程的窗口消息钩子，在原输入窗口的线程内读取或激活指定配置，并确认实际配置标识。它不读取输入框文字、不记录输入内容，不更改默认输入法或系统参与列表。仅改变 BrimDeck 自身线程的状态或返回一个成功请求，都不会被当作目标窗口已切换成功。

模块沿用原灵动岛窗口、动效、主题与设置控件。切换时暂时展示纵向列表，原页面及其配置保留。

## 构建与验证

需要 .NET 10 SDK、Visual Studio 2022“使用 C++ 的桌面开发”工作负载及 Windows SDK。原生组件的源代码位于 `src/BrimDeck.InputMethods.Native`，由 `build/BuildInputMethodNative.ps1` 在常规构建时生成；分发时须包含 `BrimDeck.InputMethods.Native.dll`。

```powershell
dotnet build BrimDeck.sln -c Release
dotnet run --project tests/BrimDeck.Tests -c Release --no-build
dotnet run --project tests/BrimDeck.MediaTests -c Release --no-build
dotnet run --project tests/BrimDeck.WindowsTests -c Release --no-build
```

自动检查覆盖配置复制、循环顺序、排除、按键状态、TSF 枚举和原生协议布局。快捷键、管理员窗口、全屏、多屏与不同 DPI 还需实体环境验证；不能用逻辑检查代替这些实测。
