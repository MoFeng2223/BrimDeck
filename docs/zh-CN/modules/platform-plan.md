## 目标与实施范围

将现有 DLL 模组能力升级为可长期演进的 BrimDeck 插件平台：插件能够增加与内置功能平级的页面、收起态内容、命令、设置和通知，用户能够统一管理、排序、授权、更新及卸载，作者通过公开 SDK 完成开发，不依赖主窗口私有实现。

按七个阶段逐项实施，不做一次性大重写。**每阶段必须交付可用功能、迁移规则和真实验证结果，未通过不得提前宣称完成。**

### 前提约定

- 用户界面逐步统一使用「插件」，但**保留 Module 项目名、程序集名和现有公开类型**，避免为名称统一破坏加载与二进制兼容。
- 保留实际数据目录中的 `mods/`、`modules-data/`、`modules-cache/`，不立即改为 `plugins/`；未来确需更名时另做有记录的迁移，**不能同时扫描两处制造重复插件**。
- 插件市场、自动网络更新和进程外沙箱**不在本轮范围**；通知完整能力有独立依赖门槛。

### 当前基线与必须先补的缺口

已有：独立程序集发现、内容摘要批准、依赖排序、激活贡献暂存、资源清理、异步视图、实际可见性、基础设置、只读快照、短时提醒、启动恢复及 SDK 工具。

| 范围 | 现状 | 升级目标 |
|---|---|---|
| 页面 | `DeckPages` 使用固定枚举；插件页面集中在「小程序」内切换 | 稳定 ID 的统一页面目录，每个插件页面独立管理 |
| 收起态 | 同时只选择一个活动呈现 | 多插件常驻区域与持续活动分开管理 |
| 通知 | 标题、正文、语气、时长、进度及简单队列 | 与灵动通知共用引擎、来源策略和完整交互 |
| 管理 | 已有启停、详情、性能和维护入口 | 文件夹导入、搜索、插件专属详情、授权撤销和清晰状态 |
| 卸载 | 当前流程包含删除业务数据 | 默认保留数据，显式选择删除，重试严格保留原操作意图 |
| 宿主接口 | 已有部分用量、媒体和系统只读快照 | 扩展完整只读信息、状态事件与按能力授权的写操作 |
| 验证 | 上轮基础检查通过，额外插件回归未全通过 | 全量插件回归可重复运行，并建立旧二进制与作者闭环 |

## 总体设计原则

### 身份、偏好和运行状态分离

所有贡献使用稳定、带所属插件命名空间的 ID。内置页面采用保留命名空间，插件页面采用「所属插件 + 局部页面 ID」；**显示名称和语言不是身份**。

分别保存：

- 用户启用意图与当前包内容批准
- 插件实际运行状态、兼容／依赖阻塞和慢调用诊断
- 页面显隐、顺序、尺寸及默认目标
- 收起区域显隐、顺序与用户选择的活动
- 命令快捷键、托盘展示偏好
- 敏感能力授权和通知来源偏好
- 插件自己的设置、运行数据及数据格式版本

条目暂时缺失时只做运行期回退，不覆盖用户保存的目标。停用保留偏好和业务数据；卸载是否删除数据由独立选择决定。

### 宿主与插件的责任

宿主管窗口、屏幕边缘、导航、通知调度、全局输入、布局预算、主题默认值和公共动效。插件管业务状态与被分配区域内的绘制，**不提供修改内置页面或任意操作主窗口的受支持接口**。

页面、常驻区域、持续活动、通知、设置和命令使用**不同贡献类型**，不用一个「万能视图」承载所有行为。业务生命周期与视图生命周期保持分离，多屏创建独立控件但共享插件会话。

### 安全表述必须准确

当前是**同进程 DLL 插件**。能力声明、摘要批准和授权仅约束公开 SDK，不能把任意 DLL 隔离为安全代码。首次启用未经批准的包时明确说明同进程风险；内容批准与敏感操作授权是两件事。SDK 不返回账户凭据、主程序实例、其他插件存储或任意可写设置对象。

### 增量契约而非静默破坏

新增功能进入同一能力目录，由宿主、SDK、检查器、模板和文档共同读取。优先新增可选接口、服务或带默认值的附加元数据，**不直接改既有接口必须实现的成员及公开构造签名**。

是否升级 minor 或 major 由签名和语义兼容测试决定。旧适配不能满足原语义时明确迁移并提升必要版本，不以「实验版」掩盖破坏性变化。

## 阶段一：可靠性基线与迁移基础

- 重新核对当前分支与 PR #181，记录实施起点、上游基线和无关改动；建立可回退提交，不 reset、不强推。
- 用隔离合成目录复现缓存三项失败，从**活跃加载租约、路径比较、清理结果和维护记录持久化**分别定位；保留原断言并增加最小回归，**不通过删测试获得绿色结果**。
- 修复测试产物定位：由构建输出清单或显式参数提供 notes、InspectionFixture、ModuleCheck 和 timers 的实际位置，不再从 notes 路径猜测兄弟目录；兼容常规 Release 输出与统一 artifacts 输出，缺少夹具时给出精确错误。
- 让插件回归具备明确的测试分组、退出码及结果摘要，失败不能隐藏为命令包装成功；仅在组间状态可隔离时继续收集后续失败。
- 固化当前公开 API、能力目录、序列化字段及代表性旧 DLL 基线，建立升级迁移日志和新偏好的 schema 版本。
- 审计现有停用顺序，为后续命令、授权和通知补上统一的「停止接单—取消—撤下贡献—保存收尾—释放」归属规则。保存失败保留可重试状态，不能报告安全退出成功；第三方同步阻塞不能被强制安全终止。
- 对照 `mods/README.md` 的 C01–C34 建立现状映射，区分已覆盖、待实现及明确不承诺的目标。

**主要接入点**：`ModuleFiles.cs`、`ModuleCatalog.cs`、`ModuleHost.cs`、`App.ModuleFiles.cs`、插件测试入口和构建工具。

**验收门槛**：活跃缓存不被删除；清空缓存不影响业务数据；待处理记录可重启恢复；普通输出与 artifacts 输出下插件回归都能完整执行；基础构建、Core、Media、Windows 托管及插件回归没有未解释的新失败。

## 阶段二：插件管理、安装、设置和数据安全

### 管理与导航

- 设置侧栏新增「插件」分组，位于「关于」之前；第一项「插件管理」，之后按用户顺序列出已启用插件。**停用插件留在管理列表，不占侧栏**；没有自定义设置的已启用插件仍有详情页。
- 管理列表显示图标、名称、作者、版本、启用意图和实际状态。启动中、等待依赖、需更新宿主、需重新批准、本次跳过、需重启与加载失败可区分；**慢回调是诊断，不等同于加载失败**。
- 提供安装、打开目录、刷新／重新加载、搜索。普通刷新保留未变化实例；重新加载明确说明影响范围，不暗中重启全部插件。
- 「未能加载」显示可操作原因；「已跳过」只解释安装根目录中未被当作包的项目，**不能把包内正常私有 DLL 和资源误列成垃圾**。
- 总开关关闭后折叠运行相关界面，但保留开关、必要故障信息和按需展开的文件／数据维护入口。
- 一个插件对应一个顶层详情页，多个设置贡献作为分组或子导航呈现；现有计时组件深链接通过适配保留，**不把三个组件伪装成三个插件**。

### 文件夹安装与更新

- 通过文件夹选择导入包，**安装不等于启用**。执行静态检查、身份和路径检查、暂存、覆盖确认，再交换到实际安装目录；拒绝路径越界、链接目录、重复 ID 和执行过程中包内容变化。
- 更新前保存旧包恢复点及必要迁移信息；旧实例通过停止协议退出，新内容重新确认后启动。失败可恢复旧安装包，**不能用旧程序强读已经不兼容的新业务数据**。文件被占用时保留待处理状态并提示重启，不强杀进程。
- 保留随附包收据与用户修改保护，普通第三方更新不能冒充随附包获得自动批准。

### 独立设置与详情

- 详情顶部统一显示元数据；宿主部分展示贡献、页面尺寸、能力、权限、诊断、目录和卸载入口。
- 插件业务设置默认使用宿主统一字段；需要自绘时使用新的可选局部设置视图契约，仍遵守视图生命周期与同一设置读写边界。
- 数字、布尔、选项、文本、颜色字段逐步具备共同的默认值、范围、校验和修订号；宿主表单、程序写入、导入及重置遵守相同规则。旧 `IModuleSettings` 保留适配。
- 「恢复默认」拆分为展示偏好、当前插件设置和授权管理。普通重置不删除业务数据、不自动启用其他插件、不授予权限。

### 信任、授权与卸载

- 首次启用提示同进程风险，确认绑定当前包摘要；已批准旧内容不因界面改名被误判成全新插件。
- 读取常规监控和媒体不追加逐次授权弹窗，但仍在清单和详情中说明读取范围。
- 修改主题／持久设置等敏感能力首次使用时由宿主确认，可仅本次允许、记住允许或拒绝，**默认拒绝**。无可见交互场景不连续弹框，转为待用户处理的状态，也不先执行再补问。
- 授权记录绑定插件内容身份、能力和风险版本。更新增加权限或更换内容时重新核验，不能凭相同 ID 自动继承所有写权限。
- 撤销后已有服务句柄和排队操作也失效，在真正提交前复查；不能只隐藏一个开关。
- 卸载默认保留业务数据，另设「同时删除插件数据」选择，明确停止依赖方、撤下贡献和是否存在待清理文件。**停用、卸载保留数据、卸载删除数据、清空缓存四种语义分开**。
- 手工删除包默认留下未关联数据，不沿用「包不在了就自动删除业务数据」的破坏性推断。重新安装可识别原数据，清理未关联数据必须由用户明确执行。
- 维护记录升级保存本次保留／删除选择和目录身份；旧记录不能因新默认值被解释成新的删除授权。损坏记录、写入失败和同名新目录都采用保留数据的安全处理。

**验收门槛**：安装／更新中断可恢复；卸载保留后重新安装能继续使用数据；删除只作用于已确认归属。关闭总开关不执行插件代码，仍可排错；权限撤销后旧引用不能继续通过 SDK 修改宿主。

## 阶段三：平级页面、主题跟随与预览

### 统一页面目录

- 将固定内置页面和插件页面投影为同一页面描述，包含稳定 ID、标题、图标、所属插件、建议尺寸和有界尺寸范围。保留旧 `DeckPage` 数值及配置读取适配。
- 用户可在同一列表排序、显示／隐藏、调整各页面大小并设为默认；滚轮、键盘及显式打开使用同一解析规则。**隐藏页面不停止插件业务，停用插件不擦除页面偏好**。
- 旧小程序尺寸作为旧页面的初始尺寸迁移；旧默认小程序选择有明确目标时迁到对应稳定 ID；没有可识别目标时采用可说明的临时回退。
- 页签放不下时提供「更多」，可搜索全部可用页面；导航与设置列表的排序保持一致。窗口和布局计算只纳入当前需要的有界尺寸，**不能因一个插件声明巨大尺寸分配不受控的绘制资源**；当前屏幕容不下时临时约束展示，不覆盖保存的期望尺寸。

### 主题与状态保持

- 宿主提供局部主题资源、默认背景、字体、文字层级及控件样式，公共工厂优先绑定语义颜色，**而不是只在创建时复制一次颜色值**。
- 主题、语言、DPI、尺寸变化通过上下文更新，不默认重建插件业务实例或正在编辑的控件；保留草稿、选区、校验状态和焦点。
- 插件写死颜色时不强行改写其绘制。模板默认使用语义令牌；屏幕阅读器名称、键盘导航、Tab、IME 和减少动画是共同规范。

### 深浅预览

- 为已启用、可信插件创建独立预览视图与局部主题上下文，不切换整个应用主题、不修改真实偏好、不调用重置或业务命令。
- 预览关闭后释放自己的视图资源，不终止共享业务会话。
- 旧插件依赖全局主题而不能隔离预览时**显示不支持原因**，不通过修改全局单例伪造局部预览。

**主要接入点**：`DeckPages.cs`、宿主设置模型、`MainWindow.PageSwitch.cs`、`MainWindow.Modules.cs`、`ModuleViewHost.cs` 和公共 UI。

**验收门槛**：默认项暂缺恢复、多页面独立尺寸、溢出、滚轮、深浅／高对比主题与编辑态保持；内置三页的现有行为不能回退。

> **仓库现状**：作者已完成（`2895aa6` + `a238d5e`）。详见 platform-upgrade.md。

## 阶段四：多插件收起区域与持续活动

> **这是「收起行部件流」所属阶段。**

### 新的呈现模型

- **常驻区域、持续活动和临时通知分成三个通道**。常驻区域按插件分组供用户排序和开关，插件内部排列由自身负责；持续活动可以请求展开控制；通知短时覆盖后恢复原内容。
- 现有 `IModuleActivity` 通过兼容适配接入，不要求旧计时器立即实现新接口。**明确同一内容是否由常驻区域或活动紧凑视图负责，不能重复占位**。

### 尺寸与空间算法

- 插件申报建议占用和可选紧凑样式，**宿主决定最终分配及全局上限**；定义沿边缘长度与横向厚度，避免侧边情况下继续混用「宽／高」。
- 沿用当前宿主边缘框架，向新布局上下文提供可用 DIP、方向、形态、设备缩放、内容缩放、留白、圆角和实际可见性。**设备缩放只应用一次**。
- 先保留宿主必要空间，再按用户顺序分配插件组；放不下时不显示该组，可优先使用其紧凑备选样式，**不能任意缩到不可读**。
- 显示变化采用**稳定尺寸预算**和合并失效请求，避免每秒数字变化导致其他插件反复出现／消失。超预算内容只在局部裁剪，不扩大外壳或截获区域之外的点击。
- 设置中**区分用户关闭、空间不足、规则隐藏和插件不可用**，并显示未展示的插件及原因。

### 活动与输入

- 多个活动采用确定的用户选择与回退顺序，不依赖偶然注册顺序。临时通知结束时重新核验原活动是否仍有效，不能恢复已停用插件的旧视图。
- **悬停展开仍由宿主管理**；插件处理自己区域内的点击，未处理则沿用宿主行为。区分点击、拖动、取消和键盘访问，保留 Esc、移动模式及全局输入优先级。插件不能借普通区域改变贴靠位置或吞掉整个窗口的鼠标事件。
- 外壳伸缩、形状与内容交接继续使用公共动效。**隐藏区域停止显示刷新，业务计时不因此暂停**；不使用每插件独立常驻布局轮询。

**验收门槛**：多个插件同时显示时顺序稳定；窄尺寸、长文本、方向变化、100%／150% 内容缩放和不同设备 DPI 下无越界、双重缩放及布局抖动。隐藏显示任务停止，恢复不丢会话；旧计时器控制和输入法临时结果继续正常。

> **仓库现状**：已实现并验收（`d73baf3` 起，`CompactPart.Modules` 参与排布）。三通道分离以新增 `IModuleCompactPart`
> 契约落地（`ui.compact-parts`）：常驻读数成为独立贡献类型，`IModuleActivity` 回归「持续活动」单一职责；
> 旧的 `ActivityState.Passive` 经文适配继续工作。

## 阶段五：命令、快捷键、数据、事件与受控操作

### 单一命令系统

- 插件登记稳定命令 ID、名称、说明、参数约束、可执行状态和异步执行入口。命令持有激活归属、取消与结构化结果；**忙碌、拒绝、取消、能力缺失和插件异常分开**。
- 快捷键、托盘与页面按钮调用同一命令，不分别维护三套业务回调。快捷键默认未绑定，由用户设置；复用本体录制、冲突、系统保留组合和释放逻辑，**不向插件开放任意全局键盘钩子**。
- 托盘只显示用户选择的命令。停用立即撤下托盘项并释放系统注册，保留绑定偏好；命令暂缺或快捷键冲突时说明原因，不抢占其他命令。

### 只读快照与状态事件

- 在现有 DTO 基础上逐步补充 CPU、GPU、内存、网络、磁盘和可用温度，以及媒体和 AI 用量；明确单位、时间戳、修订号及**缺失／过期／关闭状态，不把不可用写成零**。
- 订阅复用本体需求和现有采样，**不为每插件另建轮询**，不擅自启用用户关闭的传感器或服务，不暴露账户密钥和内部 store。
- 补充展开／收起、当前页面变化、主题／缩放、全屏、显示器和媒体变化。规定线程、次序、初始快照、合并与取消规则。宿主事件只能由宿主发布；插件专属页面、命令、通知事件按所属范围投递。
- 跨插件协议和任意事件窥探不在本轮开放。

### 宿主控制分级开放

- 首批提供打开自身页面／设置、请求展开、媒体播放暂停和受授权的强调色操作。返回明确结果，不交出主窗口或整个配置对象，**不允许修改内置页面布局、全局悬停规则或贴靠策略**。
- 用户显式点击命令时可以请求展示自己的页面；**后台事件不能无限抢焦点或反复展开**。长期自动化需要清晰的用户设置及相应能力授权。
- 强调色优先使用**可释放的临时覆盖**：用户手动修改最高优先级，插件停止或撤销授权后恢复用户状态，多插件争用有可解释顺序。持久设置修改使用白名单字段、校验及修订检查。

**验收门槛**：快捷键冲突可解释、停用完全解绑且偏好保留；旧命令和旧服务在撤销／替换后不可提交。只读缺失状态准确，事件不丢初始化变化或泄露其他插件专属信息；多个强调色请求与用户手动修改不会相互覆盖循环。

## 阶段六：与灵动通知统一集成

### 依赖门槛

- 本阶段依赖 notice／brim-notify 的可用实现与契约。执行前必须检查具体提交、合入状态、测试入口和维护者确定的消息语义。
- 只有通知引擎已合入目标基线，或用户明确批准某个可用提交后，才接真实适配。**前五阶段不因此停滞**。未就绪时保留旧轻量接口和明确的可选能力查询，**不另写第二套假兼容通知系统**。

### 统一入口与来源

- 插件进程内调用公共服务，不启动 `BrimDeck.Notify.exe`；进程内和外部工具共享消息模型、调度及视觉引擎。
- 来源由宿主依据插件身份生成，**不接受插件冒充其他来源**。每插件可分别配置开关和策略，遵守免打扰、全屏、应用规则及频率限制；优先级不绕过用户规则。队列有界，沿用统一引擎的公平性、过期与同优先级次序。

### 消息和动作

- 普通通知支持标题、正文、来源、类别、优先级、受校验图标与进度。
- 同键更新按「所属插件 + 消息键」定位；更新不反复入队、鸣响或升级优先级。明确取消、完成、过期和不可用结果。
- 按钮调用有效的插件命令或本次会话回调；停用、更新和撤权后旧动作不可执行，不能持有旧视图及整个插件实例。
- 临时消息绑定激活代；需要跨重启的动作只存稳定命令 ID 与受校验参数，**不序列化委托**。

### 倒计时、秒表和日程

- 统一引擎托管计时与插件自己计时是两种明确模式，**同一个任务只有一个时间权威**。
- 支持倒计时到期再提醒、取消／稍后提醒，秒表停止，以及日程提前提醒。为每类定义睡眠、系统时间改变、时区／夏令时、重启和错过时点的策略。
- 持久日程只保存必要数据和明确的归属。插件停用时撤销待展示通知和动作；**不会为了到点回调自动启用插件**。

**验收门槛**：与 brim-notify 对同等消息展示一致；消息更新不重复闪动，通知覆盖后恢复正确活动，限流和来源设置一致。按钮迟到、插件更新、关机恢复、睡眠、错过日程、取消／稍后提醒均有确定结果。
