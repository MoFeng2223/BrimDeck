# 模组系统（测试中）

面向作者的三篇主文档：[开发与贡献指南](modules/contributing.md)、[API 参考](modules/api.md)、[平台规范](../../mods/README.md)。配合独立 SDK 开发包，可在仓库外构建、检查和安装模组，无须阅读宿主源码。指南包含时钟、计数交互、Codex 用量提醒三个完整工程，模板直接由文档生成。平台规范另列维护者规划，其他主题文章为可选深入材料。

上次模组启动未完成时，再次打开会先询问是否“本次不加载模组”。它保留原有开关与批准，管理页仍可关闭问题模组。主动恢复可用 `BrimDeck.exe --no-modules`；此参数只影响本次运行。详细规则及作者工具见[启动恢复与静态检查](modules/checker.md)。

模组是独立程序集，通过公开契约向 BrimDeck 注册页面、持续活动、小组件和设置。默认随附的独立模组 `timers` 包含完整番茄钟、倒计时和秒表，通过与第三方相同的加载流程运行。它们共享一个计时会话，但不依赖音乐页、监控页或主窗口的实现。

## 使用与安装

设置侧栏的「工具 → 模组」提供总开关、刷新、模组文件夹和运行状态。计时器原有的「小程序」总控、拖动排序及三个组件的独立设置继续保留。外部模组设置可明确放在模组或小程序下，支持独立图标；多个组件共享设置只显示一个入口。关闭组件可隐藏关联设置，独立的模组设置继续可用。

点击「打开模组文件夹」，将每个模组放进一个独立目录，目录内至少包含 `module.json` 和入口 DLL。刷新后手动启用。首次发现不会执行模组代码；模组文件变化后，需要刷新并重新启用。依赖也需要分别启用，不会自动启用其他模组。

```text
mods/
  sample-notes/
    module.json
    BrimDeck.Sample.dll
    BrimDeck.Sample.Helper.dll
    BrimDeck.Sample.deps.json
```

入口所在目录可包含私有依赖和资源。不要附带宿主程序或 SDK 的另一份 DLL。运行时使用经过内容校验的副本，因此原始模组文件可以更新；内容相同的模组重新启用时复用缓存，不重复复制。模组详情显示数据和缓存占用，可清空缓存或卸载；当前未提供安装市场。

“清空缓存”保留业务数据和运行状态，立即删除未使用的加载副本；正在使用或被占用的文件排入清理记录，下次正常启动、刷新时继续。占用数字按需后台计算，不每秒扫描磁盘，无法读取时显示破折号。

“卸载模组”确认后停止它与依赖它的模组，移除安装文件、全部业务数据、缓存及启用／批准记录。文件先转入独立待清理目录，删除失败保留记录；某个 DLL 被占用不阻止其他数据清理，界面不会把待清理说成已完成。再次正常启动或刷新继续处理，重试只针对旧目录，不删除后来重新安装的数据。随附模组卸载后不会自行装回，可用“恢复随附模组”明确恢复。

卸载按目录身份确认归属；后来新增或无法确认归属的目录会保留并明确提示，可刷新后重新确认卸载。维护记录或设置未能写入时，不把内存修改当成已经落盘；旧任务不会接管原来不存在的新数据目录。操作正在进行时，其他操作会明确提示稍后重试。总开关关闭后刷新也会重试清理，不会因此加载模组。

对已经登记过的模组，在正常启用系统并刷新发现时，若安装文件夹确实消失且扫描没有发现错误，会按手动删除处理并清理对应数据与缓存。重命名后仍能找到相同 ID 的包会保留数据；清单损坏或无法扫描不会被误判为卸载。

这是应用内运行的 WPF 模组，只启用自己信任的代码。资源清理与普通异常处理不能隔离死循环、进程崩溃或任意文件访问；内容确认也不是代码签名或安全沙箱。

## 工程边界

管理页以紧凑卡片展示状态、版本与开关，点击名称或箭头展开说明、组件、设置入口和运行摘要；展开状态在刷新及主题切换后保留。「性能监控」提供启动耗时、最近五秒平均回调用时、最长回调、调用总数、慢调用（至少 16 ms）和错误次数。累计值覆盖本次应用运行，关闭模组后仍保留，重新启动应用后重新计算。

启动耗时包含加载、激活及异步等待，是经过时间。运行统计覆盖宿主管理的同步回调、事件、定时任务和视图调用，嵌套调用只归入对应模组一次；它不代表独立的 CPU 使用率，也不包含模组自行创建的后台任务。错误总数独立于最多 200 条的错误记录。

性能采集使用固定大小的五秒窗口，不创建后台采样计时器、不记录逐条调用历史、不持续写盘。设置数值每秒就地更新，离开模组页、最小化或关闭设置后停止界面刷新。

| 工程 | 职责 | 可以依赖 |
| --- | --- | --- |
| `BrimDeck.Modules.Abstractions` | 模组入口、上下文、清单、事件和存储契约 | .NET |
| `BrimDeck.Modules` | 扫描、依赖排序、激活、贡献注册、清理、程序集加载 | Abstractions |
| `BrimDeck.UI` | 公开界面契约、公共控件、主题与动效 | Core、Abstractions、WPF |
| `mods/timers` | 三个计时器的页面、设置和持续显示；独立领域库管理会话 | Abstractions、UI、自有领域库 |
| `BrimDeck` | 应用组装、窗口外壳、导航和设置呈现 | 上述工程 |

模组不能引用 `BrimDeck` 主程序，加载器会拒绝这种直接引用。宿主通过 `ModulePage`、`IModuleActivity`、`ModuleWidget`、`IModuleSettings` 交互，不直接访问计时器页面。修改共享 SDK 或共享主题仍可能影响所有使用它们的页面；这些公共变更需要回归测试。

## 清单与依赖

```json
{
  "apiVersion": 1,
  "id": "sample-notes",
  "name": "Notes sample",
  "version": "1.0.0",
  "assembly": "BrimDeck.Sample.dll",
  "entryType": "BrimDeck.Sample.NotesModule",
  "dependencies": []
}
```

`id` 使用小写字母、数字和连字符，最多 80 个字符；`builtin-` 留给内置模组。版本使用 .NET `Version` 可解析的格式。依赖支持 `minimumVersion` 和可选的 `maximumVersionExclusive`（不包含上界），不支持任意版本范围表达式。

当前契约为测试版 1.6，能力目录统一管理接口名称、权限和契约信息，既有同步页面和 1.1 数据接口保持兼容；省略 minor 的旧清单按 0 兼容。入口类型实现 `IModule`，提供公开无参构造函数。依赖缺失、未启用、版本不符、循环或激活失败时，依赖方不会启动；其他正常模组可继续运行。每个模组最多 2000 个文件、64 MiB，不支持链接目录和链接文件。

## 激活与资源生命周期

`ActivateAsync` 接收本次激活专用的 `IModuleContext`。注册 ID 最终变成 `模组ID:局部ID`；不同贡献类型可以复用局部 ID，同一类型不能重复注册相同 ID。激活期间的贡献先暂存，成功后一起发布；失败会撤销本次注册。

- 用 `context.Register<T>` 注册贡献，返回的句柄可提前撤销，撤销后可再次注册同一 ID。
- 用 `context.Every`、`Subscribe<T>`、`Own`、`OnDispose` 管理模组级资源。停用时先取消生命周期，再按相反顺序清理。某个清理失败不会阻断后续清理。
- 只有页面存活期间需要的计时器、事件和资源，应交给 `ModuleViewContext`；页面卸载或模组停用时自动释放。自行订阅的外部事件必须通过 `OnDispose` 或 `Own` 登记解绑。
- 会话数据放在模组实例中，视图只负责呈现。导航离开会销毁视图，不会销毁模组或计时会话。每个显示器创建独立视图，共享同一会话。
- 页面挂载、刷新、布局和释放的普通异常会被记录。1.3 起启动超过 5 秒标记为慢并继续等待，晚完成仍正常运行；无关模组独立启动，主窗口先显示。停用会取消本代令牌，旧实例迟到不会覆盖新实例；同步阻塞不能被强制中止。

当前桌面宿主在 UI 调度线程调用生命周期与视图。耗时操作应异步执行，更新 WPF 控件时返回其调度线程。后台任务必须响应 `context.Lifetime`，避免停用后继续修改自身或外部状态。宿主会拒绝已结束上下文的注册和存储写入，并立即释放迟到的清理资源。

## 页面、活动与设置

`ModulePage` 提供标题、顺序和视图工厂。视图实现 `IModuleView`，在 `SetViewport` 中适应宿主给出的空间；不要自行操作主窗口。多个页面通过统一的选择菜单切换。

1.4 支持 `ModulePage.Async` 和 `IModuleAsyncActivity`：页面异步准备期间显示统一等待提示，完成后平滑接入；切页或停用立即取消，迟到页面不会重新出现，也不会结束后台计时。外部便笺示例的「示例说明」可以体验这一路径。等待期间改变尺寸会使用最后一次布局，设备缩放与内容缩放分别处理。

`IModuleActivity` 提供收起态与展开态视图，以及活动状态、进度、强调色和完成序号。宿主管理展开、收起、位置、通知优先级和内容交接；模组管理内部内容。外壳同时呈现一个活动，优先显式选择的活跃 ID，否则首个活跃项；展开视图使用结构化 `ModuleViewport`，可用尺寸为 320 × 76 DIP。临时通知结束后恢复持续活动。

模组可以通过权限受控的 `IModuleUsage`、`IModuleMedia`、`IModuleSystem` 读取本体只读快照，并用 `IModuleNotifications` 显示短时动画提示。完整示例见[用量提醒](../../mods/usage-alerts/README.md)，包括 Codex 自定义阈值和周期去重；具体能力和限制见[API 参考](modules/api.md#9-本体数据与岛内提醒)。

`ModuleWidget` 提供组件开关；模组决定切换时注册或撤销哪些页面。`IModuleSettings.Visible` 控制设置页是否出现。设置字段支持数字、布尔、选项、文本及颜色，宿主使用统一控件呈现；范围、写入和重置逻辑由模组负责。页面可通过上下文回调打开设置或活动。

`BrimDeck.UI` 提供 `ModuleUi`、公共控件与主题资源。内容交接、数字滚动和按钮反馈沿用现有动效，并遵守应用与系统动画开关。

## 数据与兼容

模组偏好及运行快照位于应用数据目录下的 `modules-data/<id>/`。`context.Storage` 使用独立 JSON 键、单文件 1 MiB 限制和临时文件替换写入；它不提供跨文件事务。缓存位于 `modules-cache/<id>/<内容摘要>/`，原始模组目录为 `mods/`。

内置计时器继续读取既有小程序偏好，并只迁移一次旧的 `timer-session.json`。会话变化、暂停和退出时保存，显示脉冲不会每秒写盘。睡眠、退出和重启后保持暂停，等待手动继续。关闭模组系统会释放会话并保存暂停进度；关闭正在运行的计时组件或原「小程序」开关则沿用原行为，结束该会话。

旧页面枚举数值保留，新增模组偏好具有默认值、规范化与深复制。现有音乐和输入法功能仍由原服务管理，本轮没有将其强行迁入模组。

## 注册表、事件和服务（契约 1.5）

`context.Platform()` 提供 `Registries`、`Events`、`Services` 三个入口。旧 `IModuleContext` 继续兼容，不强迫既有第三方类型实现新成员。

- 注册表：`Registries.Register<T>(id, value)` 增加页面、活动、组件和设置，返回带完整 ID 的可撤销句柄；激活失败回滚，停用时移除。
- 事件总线：`Events.On<T>(handler, priority)` 接入宿主生命周期或打开钩子。同优先级按登记顺序执行，异常单独计量。`ModulePageOpening`、`ModuleActivityOpening` 允许 `Cancel()` 阻止这次打开；它们只能由宿主发布，不暂停计时会话。
- 服务：`Services.Get<T>()` 与旧 `GetService<T>()` 共用能力、权限与激活范围。`IModulePresentation.Invalidate()` 刷新动态组件顺序、开关和设置可见性，合并刷新请求，不重新启动模组。

默认计时器是[完整参考模组](../../mods/timers/README.md)，不是获得特殊宿主权限的示例。源码统一放在 `mods/timers`、`mods/notes`、`mods/usage-alerts`；每个可安装目录都包含自己的清单、项目和说明。
