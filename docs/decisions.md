# 设计决定

本文记录仍然有效的设计决定。每条说明"做什么"和"为什么"。实现位置见 [architecture.md](architecture.md)。修改相关行为时，请同步更新对应条目。

## 项目范围

**独立实现，不复制参考项目的代码。** BrimDeck 只参考同类 macOS 应用的产品形态、交互方式和数据来源思路，不复制、翻译或移植其源代码，代码与界面中也不出现其名称。
原因：该参考项目采用 GPL v3，与 BrimDeck 的 Apache 2.0 许可证不兼容。

**只支持 Windows 11（x64）。**
原因：缩小兼容范围。律动条使用的按进程音频采集需要 Windows build 20348 及以上，面板固定到所有虚拟桌面使用的 Shell 接口也只在当前系统上验证。

## 数据与凭据

**数据统一保存在 `%LOCALAPPDATA%\BrimDeck`，按当前用户解析路径。其他应用的数据位置自动定位，设置中不提供路径配置。** 仅在设置了 `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`ZCODE_HOME`（绝对路径）时改用该目录。
原因：与这些应用自己的约定一致，避免用户填错路径。

**手动来源的 API 密钥用 Windows DPAPI（CurrentUser）加密后存入 `secrets.dat`；`settings.json` 只保存一个随机的密钥版本号。** 删除条目或更换配额来源时删除原密钥。
原因：设置文件可能被复制或查看；DPAPI 把密钥绑定到当前 Windows 用户。

**其他应用的登录信息只读使用：不写入磁盘，不修改、续期或注销。** Claude 桌面版的登录缓存用当前用户的 DPAPI 在内存中解密，只选用当前账户、`api.anthropic.com`、含 `user:profile` 权限且未过期的令牌。
原因：不影响原应用的登录状态，也不让令牌出现在 BrimDeck 的文件中。

**本地数据库一律以只读方式打开。**
原因：Cursor、ZCode、Antigravity 的数据库由原应用使用，BrimDeck 不能改变其内容或锁定它们。

## AI 用量

**每个看板条目分别选择"配额来源"和"统计应用"，两者的快照分开保存，互不替代。**
原因：配额与用量常来自不同地方（例如中转站的额度与本地客户端的 Token 记录）。一方读取失败时，不应抹掉另一方的有效数据。

**最多 7 个条目；同一来源可以重复使用，但每轮只读取一次，模型合计按统计应用去重。**
原因：每列至少 150 DIP，面板最宽 1200 DIP，7 列是能同时放下的最大列数。重复条目不应增加请求次数或重复计算费用。

**所有来源共用一个 60 秒刷新周期。Claude 不再单独使用 5 分钟间隔。失败不另设重试或递增等待，下一个周期再读取。**
原因：一个周期便于理解，也便于控制请求量；各来源的限流由各自的处理规则应对（见下两条）。

**读取失败时保留最近一次成功的结果，并标明读取时间；旧数据不触发额度提醒。** 手动来源按请求键保留；ZCode 按账户保留，慢请求在后台完成，换账户时丢弃；Claude 只在内存中保留，登录失效时清除。
原因：短暂的网络或服务故障不应让面板变空，但必须让用户知道数据不是最新的。

**脚本来源收到 HTTP 429 时，在 `Retry-After` 指定的时间之前不再请求（未指定时 60 秒）。**
原因：遵守站点的限流要求，避免密钥被封禁。

**Claude 配额的读取顺序：先用 Claude Code 的登录，失败后用 Claude 桌面版的登录。** 同一令牌每轮只请求一次；桌面版遇到限流或网络错误时不再尝试其他令牌，只有令牌失效或权限不足时才换下一个。一个来源成功后立即使用其结果，不合并两个来源。
原因：两者都可以独立提供账户配额；逐个尝试所有令牌会在限流时放大请求量。

**Claude 不建立自己的配额缓存文件。接口限流、超时或故障时，显示本次运行中最近一次成功的结果，或 Claude 桌面版自己写入的 `plan-usage-history.json` 中较新的 5 小时与每周使用比例，并沿用上次接口读取中仍未到期的重置时间。**
原因：该历史文件由桌面版定期写入，读取它不需要额外请求；它不含重置时间，因此只能沿用接口给出的时间。

**不生成数据。** 未知的值不显示为 0；没有总额的余额不计算百分比；某个来源不可用或未读取完整时，合计显示为"已知合计"；有记录无法计价时金额后加"+"，全部无法计价时显示"$0.00 +"；Codex 接口失败时显示的会话记录快照标明"可能已过时"。
原因：面板上的数字必须能追溯到实际数据。

**费用优先使用接口直接给出的金额；否则按单价估算。单价来自 OpenRouter 模型目录，没有内置价格表。** 每个进程第一次刷新时联网获取，之后每 24 小时一次；失败时使用缓存，不另设重试。手动添加的价格优先于目录价格。Antigravity 记录找不到完整名称时，才去掉思考档位后缀（Gemini 的 `-minimal/-low/-medium/-high`、Claude 的 `-thinking`、GPT-OSS 的 `-low/-medium/-high`）匹配基础模型。
原因：固定价格表会过时；思考档位不是单独的价格，但其他后缀可能代表不同模型，不能随意去掉。

**模型明细使用滚动列表，不分页；筛选状态只保存在当前进程，不写入设置。**
原因：滚动时表头和合计可以固定；筛选是临时查看行为。

## 自定义配额来源

**手动来源的读取逻辑都是运行在 Jint 沙盒中的 JavaScript。** 内置的智谱 GLM、Z.ai GLM、New API、Sub2API 也是脚本，只是不可编辑。沙盒不能访问文件、进程或 .NET 对象，也不能用字符串编译代码；时间、语句数、内存、递归深度、请求次数与大小均有限制（见 [custom-sources.md](custom-sources.md)）。
原因：用户脚本不可信；内置服务与自定义脚本共用同一条执行路径，便于测试。

**自定义脚本返回数组，每项直接给出显示文字（`title`、`percent`、`value`、`suffix`、`note`、`resetAt`），`resetAt` 只接受字符串；程序不重新排序，也不改写文字。**
原因：各站点的格式差异很大，由脚本决定显示内容，比程序猜测格式更可靠。

**中转站按网关程序分类（New API、Sub2API），不按站点分类。** 选错类型时提示改用另一种。
原因：同一网关程序的站点使用相同的接口。

**New API 的金额按站点 `/api/status` 的设置换算：原始额度 ÷ `quota_per_unit`，再按站点的显示货币乘相应汇率。** 读不到时按 500000 额度 = 1 美元显示，并提示单位未确认。站点以人民币显示且汇率不为 1 时，不显示账户余额。
原因：这些都是站长的全站设置；账单接口在不同修改版中是否按汇率换算并不一致，无法确定单位时宁可不显示。

**New API 的"今日扣费"从本机时间 0 点起算：每天第一次读取时从日志汇总，并记下基准，之后用累计用量减基准。** 日志为空时不显示；日志返回满 100 条且都在今天时，数字前加"≥"。
原因：New API 服务端没有"今天"的概念；每次下载日志开销大；空日志无法区分"今天没用"和"站点不记录日志"。

## 音乐

**每个播放器只有一个信息来源。控制补充只在网易云日志模式下存在，并且只提供播放/暂停、上一首、下一首。命令先发给专属连接，只有确认未发送时才改用系统媒体会话。**
原因：两个通道同时提供信息会互相冲突；命令重复发送会导致切两首歌等错误。

**网易云默认读取客户端日志；完整控制通过本机回环地址上的调试端口实现，每次都需要用户在确认窗口中明确同意。** 连接前检查端口只在回环地址上监听且属于网易云进程；连接失败时恢复日志模式。BrimDeck 通过客户端自己的退出命令正常关闭网易云，不强制结束进程，不修改网易云的设置。
原因：日志模式不需要改变网易云的运行方式；调试端口会暴露给本机其他程序和网页，必须由用户知情后决定。

**QQ 音乐只使用其本机命名管道，并核对管道服务端进程；管道断开时整体改用系统媒体会话。**
原因：管道是 QQ 音乐自己的传输方式，不需要注入、读取内存或模拟按键。

**其他播放器使用 Windows 系统媒体会话。**
原因：这是 Windows 的通用接口，播放器是否支持某项操作以其报告的能力为准。

**音频只用于律动条，不作为媒体来源。** 优先按进程采集当前来源播放器的声音（包含子进程），不可用时读取会话峰值电平；声音只在内存中分析。
原因：有声音不等于有可显示的曲目信息；音频数据不需要保存。

**多个来源同时存在时，最近开始播放的来源显示在前；3 秒内恢复播放的来源保留原位置。用户可以手动选择或固定来源。**
原因：切歌和缓冲会短暂停止播放，不应因此改变显示顺序。

**歌词查询顺序：播放器直接提供的歌词 → 已知网易云歌曲编号时按编号查询 → LRCLIB（先精确匹配再搜索）→ 网易云搜索。** 候选须歌名、歌手一致且时长相差不超过 2 秒；最多缓存 80 首的有效结果，查询失败不缓存。QQ 音乐的歌曲只查询 QQ 音乐自己的歌词接口，查不到时显示管道提供的当前行。没有时间戳时显示可手动滚动的普通歌词，不伪造时间。
原因：优先使用最可信的来源；QQ 音乐的曲库与其他服务不一致，跨服务匹配容易出错。

**配额环放不下时先缩小，再像歌词一样往返滚动**（开头停 2.5 秒，每秒 12 DIP，末尾停 2 秒，淡出回到开头）；面板展开、正在提醒或鼠标在收起形态上时暂停。不使用逐个轮换或"+N"。
原因：往返滚动可以让每个环都完整出现，并与歌词的滚动方式一致。

**收起形态宽度固定，不显示时间。** 封面固定在最左，律动条固定在最右。
原因：收起形态的宽度固定（刘海 238 DIP、胶囊 196 DIP），这段宽度只用于配额环和音乐内容。

## 界面行为

**普通窗口最大化时默认显示指示条；无边框全屏和独占全屏时默认完全隐藏并停止悬停感应。** 每 400 毫秒检测一次前台窗口环境。
原因：面板不应遮挡全屏内容，也不应在全屏时被误触展开。

**悬停相关的计时使用 `PromptTimer`，收起状态下按鼠标坐标判断是否进入面板。** 靠近面板时每 40 毫秒检查一次，远离时按距离延长到最多 160 毫秒。
原因：`DispatcherTimer` 依赖 `WM_TIMER`，只在消息队列空闲时产生，鼠标移动时曾迟到最多 3.5 秒；逐像素透明窗口收到的鼠标消息也不可靠。

**只在 DPI 的新旧值不同时响应 `DpiChanged`。**
原因：WPF 在窗口移动或改变尺寸后会发出新旧值相同的 `DpiChanged`，响应它会再次移动窗口并形成循环。

**字号按列宽和面板高度分为五档，放不下时降一档，不裁切也不滚动；悬停提示统一在 120 毫秒后出现。**
原因：整数字号保持文字清晰；部分电脑的系统悬停时间长达 1 秒，提示需要统一的短延迟。

## 设置与语言

**`settings.json` 记录保存它的应用版本 `AppVersion`；迁移步骤按版本号标注并依次执行。升级时把旧版本的设置保存在 `Snapshots` 中（最多 5 个）；降级运行的旧版本只读写自己那份快照。**
原因：只新增设置项时不需要迁移步骤；改名、拆分或改变含义时必须有迁移。快照让用户退回旧版本时恢复旧设置，也不会破坏新版本的设置。

**首次启动按 Windows 显示语言选择界面语言：所有中文（含繁体）显示简体中文，其他语言显示英文。之后沿用保存的语言。** 没有语言字段的旧设置文件视为中文；"恢复默认"时重新检测。安装程序按同一规则在英文、简体中文之间选择。
原因：早期版本只有中文；繁体中文界面尚未提供，简体中文比英文更接近。

## 安装与更新

**安装包使用 Inno Setup，默认仅为当前用户安装。升级时先保留数据卸载旧版本，再安装新版本；卸载时询问是否删除用户数据，默认保留。**
原因：仅当前用户安装时，应用内更新不需要管理员权限；先卸载旧版本可以清除旧文件。

**每个版本附带 `update.json`（版本号、说明、安装包文件名、大小、SHA-256）。应用读取最新正式版本的 `update.json`，从该版本自己的标签下载安装包，校验大小和 SHA-256，运行前再校验一次。只有安装程序登记的副本才提供应用内更新。**
原因：防止下载内容被替换或损坏；从标签下载可以避免检查与下载之间发布新版本导致文件不一致；便携副本没有安装登记，无法由安装程序替换。

**只在用户打开设置时检查更新（两次自动检查至少间隔 30 分钟）；只有设置窗口可见、处于前台且未最小化时才弹出提示；同一版本只提示一次。**
原因：常驻面板不应在用户工作或全屏时打扰用户。

**发布版本预编译（ReadyToRun）并关闭分层编译。**
原因：分层编译会在启动几分钟后于后台重新编译常用方法，表现为首次使用播放器或展开面板时的 CPU 峰值。
