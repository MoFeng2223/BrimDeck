# 日历模组

月历 + 当日日程的独立模组，只引用公开 SDK（`BrimDeck.Modules.Abstractions`、`BrimDeck.UI`），不引用主程序。
需要契约 **1.1**、WPF、.NET 10。

## 能力

- **月历**：6 行 × 7 列固定网格，切月不跳尺寸；周一/周日开头可配；今天为实心块、选中日为主题选填色 + 强调色日号、非本月降透明度。
- **周条**：面板太矮（< 170）时自动切成单周视图，每格显示日号、事件点与前两件事；左右箭头按周移动。
- **农历与节气**：农历由 .NET `ChineseLunisolarCalendar` 换算，二十四节气由太阳视黄经二分法求解（误差约 1 分钟）；节日（春节/除夕/元宵/清明/劳动/端午/七夕/中秋/重阳/国庆/腊八）按农历或节气自动判定。
- **调休**：只有「哪天补班、哪天放假」需要人工数据，见 `Core/HolidayTable.cs`；未填的年份只是少一个「班/休」标记，节日日期仍正确。
- **日程面板**：右侧列出选中日期的事件，可新建、编辑、删除；事件按日建索引，渲染只查 42 天。
- **岛内条**：收起态贴着其它图标显示「距今天下一件事 2h15」，事件进行中显示「进行中」，今天没有未结束事项时整条不占位；展开态（320 × 76）显示日期 + 农历 + 当天项数 + 下一件事。
- **提醒**：事件开始前按设置弹一条岛内通知；同一事件只提醒一次，`RateLimited` / `NotReady` 不消耗机会。
- **vivo 日历（实验性）**：可选读取 vivo 办公套件的本地日历库，作为**只读镜像**合并进月历；默认关闭。
- **一个设置页**：设置侧栏「工具 → 模组」下的「日历」，含每周起始、农历、节日、提醒提前，以及「显示日历页面」
  「显示岛内日程」两个开关。模组**不注册 `ModuleWidget`**，所以不会被列到「小程序」下方的组件设置里；
  关掉页面开关只撤销页面注册，事件与设置都保留。

## 构建

在仓库根目录：

```powershell
dotnet build mods/calendar/BrimDeck.Calendar.csproj -c Release --artifacts-path E:/BrimDeck-build -t:GetModulePackage
```

产物：`E:/BrimDeck-build/bin/BrimDeck.Calendar/release/package/calendar/`，包含 `module.json`、
`BrimDeck.Calendar.dll`、`BrimDeck.Calendar.Core.dll`、`BrimDeck.Calendar.deps.json`。
`build/ModulePackage.targets` 会自动排除宿主与共享 SDK 的 DLL，不要再手动带上。

## 安装

在应用「工具 → 模组 → 打开模组文件夹」里新建 `calendar/`，把上面四个文件复制进去，刷新后启用。
文件内容变化后需要刷新并重新启用；当前没有开发目录豁免。

## 数据

| 键 | 内容 | 说明 |
| --- | --- | --- |
| `events` | `{ version, events: [{ id, date, title, allDay, start, duration, category, done, source }] }` | `date` 为 `yyyy-MM-dd`；`start`/`duration` 单位为分钟；`source` 为 `vivo` 表示外部镜像 |
| `preferences` | 首日、农历开关、节日开关、提醒提前量、两个组件开关 | |
| `reminded` | 已提醒标记，最多保留 200 条 | |

位于应用数据目录的 `modules-data/calendar/`，由 `context.Storage` 读写，单键上限 1 MiB。

程序与数据是分开存放的：删除 `mods/calendar` 只卸载程序，**不会**删除这些文件；重新安装后事件与设置会恢复。
模组分发包里不含任何用户数据（只有 4 个程序文件），事件只存在于各人自己的机器上。要彻底清除，见文末「卸载」。
读取使用 `ReadResult<T>`：文件损坏时**只读不覆盖**，页面底部显示「数据只读」，故障写入模组诊断。
手工编辑 `events` 时，无法解析的行会被丢弃，其余字段夹取到合法范围，不会整份失效。

## 布局分档

| 面板 | 行为 |
| --- | --- |
| 宽 ≥ 500 且高 ≥ 190 | 月历在左、日程面板在右 |
| 宽 ≥ 500 且高 < 170 | 周条在左、日程面板在右；每格显示前两件事 |
| 其余（窄或中等高度） | 单页显示月历，点某天进入当日日程，左上角「‹」返回 |

格子高 ≥ 30 时显示农历/节日，≥ 20 时显示事件点（最多 2 个，位于日号右侧）。没有滚动条：
日程列表按可用高度分页，翻页在面板右下角。

## 交互与无障碍

- 所有可点区域都是真正的 `Button`：复用宿主 `PanelHover`/`PanelPressed` 的淡入反馈（`Feedback`）与
  `PanelWideKeyboardFocus` 焦点环，回车/空格可激活，读屏能读出名称。
- 网格键盘：方向键移动选中日（±1 / ±7 天），`Home` 回今天，`Enter` 在当天新建，`Esc` 从日程返回月历。
- Tab 只停在选中日（roving tab stop），不在 42 个格子间逐个跳。
- 自动化名称包含日期、星期、农历/节日、事件数与「今天」。
- 动效沿用宿主语言：翻月/翻周 `Handover.Forward`/`Back`，其余重建 `Morph`，日程刷新 `Brighten`，
  弹窗 `Appear`；关闭应用或系统动画时全部即时生效（不依赖动画的初值）。
- 明暗主题全部取自主题资源（`PanelPrimary/Secondary/Tertiary/Fill/FillSelected/Accent/Surface/Popup`），
  没有硬编码灰阶；唯一固定色是五个类别色与删除红。

## 外部日历（实验性，默认关闭）

在设置里打开「读取 vivo 日历（实验性）」后，模组会只读打开 vivo 办公套件的本地库
（`%APPDATA%\pcsuite\database\CalendarSync.db`，可用环境变量 `BRIMDECK_VIVO_DB` 指向别处），
把 `Instances` / `Events` 里 ±2 年、最多 2000 条日程合并进月历，并标 `source = vivo`。

- **只读**：只执行 `select`，从不写入、从不 VACUUM；`caldavAccount` 等账号表完全不碰。
- **只影响自己**：外部事件在列表里带 `vivo` 标记、不可点开编辑、没有删除按钮；关闭开关后立即移出。
- **准实时**：日历页打开期间每 5 秒比对一次内容指纹，有变化才重新合并；离开页面即停止读取。
- **依赖系统组件**：通过 Windows 自带的 `winsqlite3.dll` 读取，不额外打包任何原生库。
- **这是非官方接口**：vivo 改版可能失效，届时开关会显示「读取失败」，本地事件不受影响。

## 已知限制

- **除 vivo 这一实验性来源外，读不到其他外部日历**。当前 SDK 没有日历服务、网络授权或账号目录访问，
  本模组不解析 Google/Outlook 的私有缓存，也不支持 `.ics` 导入（需要宿主提供文件选择授权）。
- 没有导入/导出、没有重复日程、没有跨天事件（事件只在单日内）。
- 提醒受宿主限制：每模组每分钟最多 4 条、队列 16 条，标题 60 字、正文 160 字。
- 调休表为空时不会显示「班/休」标记。

## 卸载

1. 应用「工具 → 模组」里停用「日历」；
2. 删除 `mods/calendar/` 文件夹；
3. 如需一并清空数据，再删 `%LOCALAPPDATA%\BrimDeck\modules-data\calendar\`。

`modules-cache/calendar/` 是加载器按内容摘要保留的副本，不参与发现，可留可删（宿主目前不自动清理旧缓存）。
