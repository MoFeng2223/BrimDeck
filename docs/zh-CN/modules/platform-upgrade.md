# 插件平台升级与验收记录

## 起点与版本

升级从插件分支 `codex/miniapps-plugin-design` 的 `9928eb0` 开始，对应 PR #181；工作区当时无未提交修改。该提交包含 dev `5541b7e`。执行时远端 dev 已为 `a5f1eea`，没有将新的上游变更混入本次升级。实际安装／数据／加载缓存目录继续是 `mods/`、`modules-data/`、`modules-cache/`，不同时扫描第二套目录。

阶段一契约保持 1.6；阶段二增加可选接口后提升至 1.7，既有接口必需成员、构造签名及枚举数值未改动。公共 API 和能力基线来自 `api.md` 的生成区块及 `ModuleApi.Catalog`；`BrimDeck.ModuleDocs --check` 同时检查两者。新增宿主偏好 `Modules.SchemaVersion = 1`，旧 JSON 缺字段时采用初始 schema；内容批准及既有 ID 不迁移或失效。安装清单格式、平台契约、宿主版本和业务数据版本仍是不同概念。

## 阶段一：可靠性

基线复现：402 次断言，三个缓存断言失败，随后检查器夹具路径异常，后续组没有执行。缓存路径混合 `/` 与 `\` 时，字符串比较未保护活跃目录。维护器现在先规范化完整路径，忽略大小写和末尾分隔符，也保护祖先／后代租约；清空缓存不删除业务数据。

测试构建生成 `module-test-artifacts.txt`，记录 notes、InspectionFixture、ModuleCheck 和 timers 的真实产物路径，不再由 notes 的位置推算其他工程。正常 bin 输出与统一 artifacts 输出使用同一入口：

```powershell
dotnet build BrimDeck.sln -c Release --no-restore -m:1 --tl:off
dotnet run --project tests/BrimDeck.ModuleTests -c Release --no-build -- --test-root <隔离目录> --repository <仓库>
```

可传 `--artifacts <输出清单>` 或 `--group runtime,files`；旧三个位置参数仅覆盖 notes 路径，其他位置仍从构建清单读取。0 表示所选组通过，1 表示断言／组失败，2 表示参数／产物缺失。JSON 分别列出每组的执行、失败、未选择与 UI 前提阻塞状态。UI 初始化失败时不继续依赖它的组。每次创建独立合成目录，保留结果文件用于调查，不读取真实业务数据。CI 已将插件回归列为必需步骤。

停止时先撤销接单资格、取消令牌，再逆序释放本代贡献和视图。仅同步收尾回调所在的线程可在该阶段完成最后存储写入；其他迟到任务不可写，新代不得被旧句柄覆盖。旧 `OnDispose` 出错仍继续释放其他资源并记录所属代，但维护屏障会拒绝后续删除，重复维护也不会忘记失败，要求重启后重试。第三方同步阻塞无法安全强制终止；这不是异步强停协议或进程隔离。

## 阶段二：管理与数据安全

设置侧栏以插件为单位提供详情和业务设置分组，保留组件深链接；管理页支持搜索、文件夹静态检查导入、单插件重新加载和维护。关闭总开关后不显示运行卡片，文件维护可按需展开。首次启用说明同进程 DLL 风险，内容摘要批准不等于敏感能力授权。

文件夹更新通过 `.module-updates/<事务>/` 暂存、持久日志和目录身份进行交换。启动前恢复未完成事务，先停止依赖链并保存撤权；安装不会自动批准，新内容不沿用旧摘要的敏感授权。旧包恢复点按创建时间列出，恢复入口只回滚代码和资源，必须另行确认业务数据版本兼容。文件锁或同名替换目录使操作保持待处理，不覆盖新目录。未完成的无有效日志暂存目录保留并报告，需人工检查，不猜测删除。

卸载默认保留业务数据，删除必须显式选择。重启重试保持最初选择与目录身份；手工删包不再推断删除业务数据。旧维护日志迁到版本 2，但旧删除记录不产生新的数据删除授权；已隔离的旧数据保留供恢复。未关联数据清理另行确认；清空缓存不影响业务数据。

新增 `IModuleVersionedSettings`、`ModuleSettingsStore` 和 `IModuleCustomSettings`（minor 7）。表单、程序补丁、导入和重置共用校验／修订边界；修订冲突拒绝覆盖，写盘失败不提交内存值。旧 `IModuleSettings` 保留适配。局部自绘视图沿用挂载生命周期，不增加秘密管理或任意宿主设置接口。敏感授权门有内容／能力／风险版本、仅一次或记住、撤销和提交前复查；真实可写服务随阶段五接入，当前没有凭授权门占位宣称宿主控制已交付。

安装恢复、保留卸载、修订校验和撤权有合成目录回归。新增独立进程构建生产设置窗口，不运行正常应用启动；真实管理页、设置深链接、无设置插件详情和关闭态维护均有断言。最初截图夹具重复挂载根元素失败，之后发现应用消息循环误入正常启动，已以禁止生产启动／退出的夹具修正，临时探针已移除。提交前串行验收：solution 构建 0 警告／0 错误，Core 2526 项、Media 89 项、Windows 托管 87 项、插件 546 项（另含隔离管理窗口内部 4 项）均通过，API 生成校验匹配 96 个类型和 11 项能力；这不覆盖真实硬件 DPI、多屏或完整性能矩阵。

## 阶段三：平级页面与局部主题

`DeckPageDirectory` 将三种内置页面和每个插件页面投影为同一稳定 ID 列表；保留旧枚举与原数值读取，不再通过「小程序」二级菜单选页。`Pages.Version = 1` 保存混合顺序、显隐、独立尺寸、默认和最后目标。插件暂缺只运行期回退，不改写用户目标；旧小程序没有保存具体身份时保留明确的未解析目标，不猜测第一插件是默认。旧共享尺寸作为各旧页面的初值。声明、设置与窗口预算均受宿主 440–1200 × 140–400 上限约束，屏幕实际约束不回写期望尺寸。

导航、设置列表、滚轮及 Ctrl+PageUp/PageDown 使用同一目录；空间不足显示「更多页面」，可搜索，当前隐藏于溢出区的页面将选择胶囊定位到更多按钮。布局等待仍有界，主题和语言不作为重新挂载页面的身份。

minor 8 增加可选页面尺寸、图标、局部主题支持声明及 `ModuleAppearance` 上下文。每次挂载有局部语义资源、设备／内容缩放、语言、减少动画与预览标记；公共文本、数字和控件使用动态语义颜色。深浅预览只对已激活且声明支持的页面开放，不改全局主题，不重新激活业务，禁用预览输入与导航；仍会执行可信 DLL 的视图代码，不是沙箱。未声明支持的旧页明确显示原因。计时和日历编辑器避免换肤重建，布局／语言重建延后至输入调整完成，保留当前控件、选区与输入法会话。

专项回归覆盖稳定目标恢复、独立尺寸、保留偏好、恶意尺寸、混合顺序、溢出胶囊、局部资源和编辑控件身份。设备 DPI、多屏、Windows 10/11 与真实 IME 仍需设备验收，合成选区检查不替代这些路径。
